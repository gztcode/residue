### 一个反复出现的模式（本轮最值得记的一条）

**DAC 普遍以「有几个」立标，而 AC 以「是哪几个」立标。凡数量相等而成员不同之处，DAC 一律判通过。** 已实证三处：

| 处 | AC 规定的成员 | 实现的实际成员 | DAC 判了什么 |
|---|---|---|---|
| DAC-40 | 各来源占用量 / **可再生物料清单** / **不可再生物料清单** | uv cache / npm/_npx / pipx run（三张**来源**卡） | 「三区块齐备，3 个 metric 成立」→ 通过 |
| DAC-47 | ①参与 ②来源 ③样本数 ④门槛 ⑤**L2 误判数** ⑥L0误判·检查 ⑦结论 | 来源 / 判定域 / 样本·总量 / 门槛 / **观察期** / L0误判·检查 / 结论 | 「七项」数量对上 → 不再核成员（虽整体判不通过，但错因写的是「非 metric 槽位」，不是「成员错」） |
| DAC-43 | 清理策略参数 + 规则版本 | 清理策略参数 + 规则版本（后者本期不交付） | 「两区不重叠」→ 通过 |

**修法不是逐条改，而是给 DAC 加一条通用判据**：「凡 AC 枚举了成员的 N 项集合，DAC 条目必须**逐项点名成员**，不得只写项数。」这一条能一次性堵住上面三处，也能防住后面还没出现的第四处。**我把它列为建议项 S-08，处置意见 = 转 DAC v2.0 落地。**
