# Residue · K2 交底裁定（程必达）

> **性质**：这是对 K2 交底单 14 条异议（客户端 5 + 质量 9）的**逐条裁定**。**裁定不替岗位接受范围与工时**——那是他们的签字权；我只裁定「要不要改契约」「输入给不给」「口径怎么写」。
> **原则**：**「同一事实两处写、只能改一处」** → 优先改**技术方案**（R2 是本次产出，可动）；**冻结 PRD 的一律走 CR-022**，不在实现层私了。

---

## 一、客户端 5 条异议的裁定

### 异议 1 · A-4 断点水位方案 —— **裁定：改技术方案 §5.5，不重开 R2 评审**

**实测证据**：200 项目录中断后续扫，合并结果 **36 项 vs 基线 120 项，漏 70%**。根因是 `readdir` 返回的是 **APFS 哈希序，不是字典序**——R2 §5.5 写的「已完成子项名字典序最大值」作水位，**在真实 APFS 上必然失败**。

**裁定**：
1. **技术方案 §5.5 的水位机制改为「已完成名字集合 + 三项摘要自证」**，由 A-4 实现（申必许已在实测中验证该方案三项全一致）。
2. **契约签名不变**（IF-01 / IF-02 的入参出参、AC-20 的验收口径三项一致）→ **属实现层修正，不重开 R2 评审**。申必过的请求成立。
3. **A-4 工时 3 → 3.5 人日**成立（返工 + 自证载体）。
4. **连带**：R2 §7.2 的 `DT_UNKNOWN` 一行（3.3 万次 × 15 µs = 0.5 s）基于同一错误假设——实测 APFS 上 `DT_UNKNOWN = 0`。**§7.2 该行改为「实测 0，保留退回路径」**，不删（保留是为了非 APFS 卷的兼容）。

### 异议 2 · A-9 视觉输入缺失 —— **裁定：选 (a)，且现在补一份最小视觉基线**

**裁定：采 (a)「七页骨架 + 语义位占位」**，理由：申必过的判断成立——随机视觉落地后必然全页重刷，比现在多花 2 人日更贵；R2 §14 自我限制第 2 条本就把 7 页界面细节划归设计基线。

**但 (a) 不等于「没有视觉」**。我补一份**最小视觉基线**（不是完整 R1.5），只定四件事，够让骨架不是白板：
1. **字号/行高/间距刻度**：正文 13pt、行高 1.4、间距 4 的倍数（4 / 8 / 12 / 16 / 24）。
2. **语义色**：沿用现有设计稿 Ardot 744401601062075 的深色 Linear 风格（单信号色 `#5E6AD2`）；**状态色只定「危险」与「中性」两档**（不新增第三档）。
3. **八态九态的视觉映射**：空 / 加载 / 错误 / 无权限 / 超限 / 并发冲突 / 超时 —— 每一态**一行文案 + 一个图标位**，具体文案随 R1.5 定稿。
4. **语义位类型化**（申必过的建议，采纳）：`SemanticSlot` 枚举收敛「界面能显示什么」，让「L4 禁止算术」**从靠纪律变成靠类型**。

**这是范围变更，需你拍板**（见文末「需你决定」第 1 条）。R1.5 完整设计基线仍缺，**R3.8 设计走查前必须补**。

### 异议 3 · A-7 载体归属 —— **裁定：(i) 改造，且老数据可丢弃 → 2.5 人日**

**理由**：现有 `state.json` 是全 JSON，`state.residue` 是「JSON 头 + 段表 + 二进制段 + CRC」——**两个不同载体**。选 (i)（改造）而不是 (ii)（并存），理由：
- 并存会产生**两个真相源**（`state.json` 与 `state.residue` 各存一份七量）→ 这正是 R2 §19 自己总结的「同一事实两处写」的复发模式；
- 现有 `state.json` 是**开发期产物，从未发布**（产品未上线）→ **老数据可丢弃，不需要迁移读路径**。

**裁定**：A-7 = **改造现有 `StateStore`**，删除 `state.json` 路径，不写迁移读路径。**2.5 人日成立**（不 +0.5）。

### 异议 4 · `DT_UNKNOWN` 不可构造 —— **裁定：验收口径改写，不改产品行为**

**裁定**：验收口径改为「**`M_unknown` 计数机制存在且被单测覆盖（注入构造）**」——产品**保留**退回 `lstat` 的路径（非 APFS 卷仍需要），但**验收不要求在 APFS 真机上自然出现**。单测用注入构造覆盖该分支。

**理由**：要求真机上自然出现 `DT_UNKNOWN` 是把「产品的兼容路径」误当成「验收目标」。单测覆盖分支 + 真机验证主路径，是标准做法。

### 异议 5 · `vnodeid` 字段不存在 —— **裁定：成立，改技术方案（不重开 R2 评审）**

**实测证据**：macOS SDK 的 `struct vnode_info` 只有 `vi_stat / vi_type / vi_fsid`，**没有 `vnodeid` 字段**。R2 的 ADR-03 / IF-03 写的「取 `vnodeid`」在字面实现下拿不到。

**裁定**：**文件身份统一为 `(设备号 vst_dev, inode vst_ino)`**，产品自建 `UInt64` 键做倒排。**ADR-03 / IF-03 同步改写**（属实现层事实修正，IF-03 的签名与验收口径不变 → 不重开 R2 评审）。

**连带（同一事实两处写，必须同改）**：
- 技术方案 ADR-03 / IF-03 / §3；
- 质量交底单 §2.2 提到的 `PROC_PIDLISTFDS` **返回值是字节数不是元素数**（实测 24 B/项）——**写进 IF-03 的实现约束**，否则第二个实现者还会踩。

## 二、质量 9 条异议的裁定

### 异议 1 · AC-19 命令白名单不封闭 —— **裁定：我给全集**

**问题**：PRD AC-19 用「`uv cache dir` / `npm cache ls` / `npm config get cache` / `brew --cache` **等**」开放结尾，R2 只定义了载体字段没定义全集 → 「集合外命令数 = 0」不可判。

**裁定：封闭白名单如下**（我给，可直接回填为用例期望读数样例）：

| 命令 | 参数形态 | 允许 | 归属来源 |
|---|---|---|---|
| `uv cache dir` | 无 | ✅ | `uv` cache |
| `uv cache clean --dry-run` | 无 | ❌ **不纳入**（带清理语义，即使 dry-run 也不进白名单） | —— |
| `npm config get cache` | 无 | ✅ | `npm/_npx` |
| `npm cache ls` | 无 / `--json` | ✅ | `npm/_npx` |
| `pipx list --json` | 无 | ✅ | `pipx` run |
| `brew --cache` | 无 | ✅（**仅在 `brew` 存在时**；不存在 → 记 `E-107`，不判失败） | `brew` cache |

**白名单之外的任何命令 → 该来源记 `E-107`（「只读定位 / 能力探测失败」），不删除、不点亮。** 这也让 AC-19 的「集合外命令数 = 0」有了唯一读法。

### 异议 2 · AC-16 本期不交付 vs B-1「逐条覆盖」 —— **裁定：B-1 口径改写（交底单层面，不改 PRD）**

**裁定**：B-1 验收口径改为「**AC-01 ~ AC-15 + AC-17 ~ AC-20 逐条覆盖；AC-16 挂一条『本期不交付』说明行**」。**冻结 PRD 不动**（AC-16 的不交付是 CR-009 已裁决的）。

### 异议 3 · V2 / V3 / V6 未定稿 —— **裁定：分两步**

**裁定**：
- **V6（「持有」判据集合）我现在就能定**（它是技术事实，不需用户拍板）→ **V6 = 「该候选的 `(dev, ino)` 出现在任一同 uid 进程的 fd 集合中，或候选（目录）是任一同 uid 进程 cwd 的祖先路径」**。写入 R2 §13。
- **V2（单次容量上限）/ V3（条目数上限）需要你拍板**（属业务取舍，不是技术事实）→ 见文末「需你决定」第 2 条。**在此之前，用例集按「注入位 + 判据结构」冻结，数值后填**——查必究的这条主张成立。

### 异议 4 · 缺三类注入点 —— **裁定：全部成立，我补「测试注入点约定」**

**问题**：① 时钟/观察期——观察期已满 = 14 个日历日，用例跑不出前置；② 电量——macOS 无注入点；③ L2 推断值——本期无通道。这三类不补，AC-04 / 08 / 09 / 02 / 20 的用例写出来就是恒真。

**裁定：技术方案增一节「测试注入点约定」**（**只在测试构建生效，只影响可观测字段，不改判定逻辑**，这是查必究自己给的边界，我采纳）：

| 注入点 | 方式 | 生效范围 |
|---|---|---|
| **时钟 / 观察期** | 环境变量 `RESIDUE_TEST_CLOCK`（ISO 时刻）+ `RESIDUE_TEST_COUNTED_DAYS`（直接置计数日） | 只在 `#if DEBUG` + 测试构建；`Metrics.ObservationClock` 读取；**不影响 `a` / `b` / `K` / `J` 的算法** |
| **电量 / 电源** | 环境变量 `RESIDUE_TEST_POWER`（`normal` / `lowBattery` / `onBattery`） | 只影响 `Scheduler` 的低电量分支与 `E-103` |
| **L2 推断值** | 环境变量 `RESIDUE_TEST_L2`（来源名 → 推断值 JSON） | 只影响 AC-02 判据 3 的读数；**不进任何判定逻辑**（L2 本期不构成门槛） |
| **来源枚举** | 环境变量 `RESIDUE_TEST_SOURCES`（封闭枚举子集） | 决定判定域成员，用于构造「空域」与「新入域来源」 |

**这直接关掉质量标出的 10 条恒真/恒假里的大部分。** 代价：产品构建必须剥离这些注入点 → **R2 §10.1 增一条发布准入检查**（Release 构建里这些符号命中数 = 0）。

### 异议 5 · AC-15 预检取值来源两读 —— **裁定：写死两行（这是我的错，R2 确实没写）**

**问题**：IF-07 说「预检值取首检时刻 `t1`」，IF-08 说「上限必须在删除前预估」——若预检是**实时递归值**，`rename` 根本不发生，「`t2` 实测超限 → 移回原位」这条判据**永不可达**；且预检拦截时的 `action` / `blockedReason` 取值未定义 → **预期两读**。

**裁定（技术方案写死两行）**：
1. **IF-08 的「删除前预估」取值来源 = `t1` 预览值**（即 IF-07 的递归字节，取自首检时刻的快照并**随候选一起缓存到执行点**），**不是执行时刻的实时递归值**。→ 这样「预检通过 → rename → `t2` 实测超限 → 移回原位」这条路径**可达**，AC-15 的判据有判别力。
2. **预检拦截（未 rename）时的记录** = `action = blocked_cap`、`blockedReason = "预检超上限"`；**rename 后实测超限而移回原位** = `action = blocked_cap`、`blockedReason = "实测超上限，已移回原位"`。两者**归为同一动作值、不同原因串**。

### 异议 6 · AC-07「内容读取记录数为 0」无载体 —— **裁定：加计数位**

**裁定**：技术方案 §5.4 的 `scan.jsonl.diagnostics` **增「内容读取次数」计数位**（本产品扫描阶段**只读元数据、不读文件内容** → 该计数恒为 0；一旦非 0 说明有实现越界去读内容 → **该项从恒真变成可判**）。

### 异议 7 · AC-08 ②″/②‴「未取得 FDA」态不可观测 —— **裁定：改判据 + 降级两条用例**

**问题**：ADR-06 明写「不做 FDA 是否授予的判定」→ 真机不授予 FDA 时同 uid 枚举照样成功 → 「L0 未判定」这个未达项**永不出现** → ②″/②‴ 预期集合恒为空集。

**裁定**：
1. **AC-08 ②″/②‴ 的 Given 改为「该来源同 uid 进程枚举失败（`E-501`）」**——这是**真实可达**的态（来源目录权限异常时可复现），且与 ADR-06 的口径一致（`degraded` 只在同 uid 失败时为 true）。
2. **文案同步**：`L0 未判定（未取得 Full Disk Access）` → **`L0 未判定（无法枚举本用户进程）`**。理由：产品已不判 FDA，说「未取得 FDA」就是**说了一件它不知道的事**，违反 N5「不把未知判为安全」的对偶要求——**不把未知说成已知**。
3. 这两条用例本轮**不降级**，Given 改完后即可构造。

### 异议 8 · AC-10「常驻监听进程退出」与 ADR-02「单进程常驻」冲突 —— **裁定：改技术方案（只能改一处，选 R2）**

**裁定**：**技术方案 ADR-02 统一为任务级表述**——「**无常驻采样任务在运行**」（不是「无常驻进程」）。**冻结 PRD 的 AC-10 进程级表述不动**（走 CR-022 一并改）。理由同前：R2 是本次产出，可动；PRD 是冻结基线，改动成本高。

### 异议 9 · B-1 工时不足 —— **裁定：成立**

**裁定**：B-1 = **4.5 人日**（原 3），B 组合计 **9 人日**。并明确 **B 组交付物 = 用例基线文档（冻结）**，执行期（14 天观察期 / 双机 FDA 态 / 有网机）**不计入本阶段**——这条查必究说得对，本阶段的交付物是「用例写对了」，不是「用例跑完了」。
