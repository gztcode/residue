## 1. 先把阻塞项的性质说准

**表面**：§6 第 434 行承载页指定漏写了一句 D2 入口的落点。

**实际**：D2 引入了「产品内唯一一个可点击、会把用户带出产品的控件」，而 7 页信息架构里**没有任何一页是它的归属**。

| 证据 | 内容 |
|---|---|
| 434 行 | 承载页指定只列五类：定时任务 / 扫描进度 / 并发两态 / U1 规则版本 / U2 文件恢复，无外部入口 |
| 436 行 | 7 页为 ①只读存储总览 ②环境明细与候选清单 ③清理策略配置 ④授权与隐私 ⑤影子观察期报告 ⑥确认清理 ⑦举证链 / 执行日志 / 文件恢复入口。**无「关于 / 版本 / 帮助 / 设置」页** |
| 327 行 | 第 ④ 页已承载 AC-11 四组信号位与常驻采样页资源占用文案，不是天然落点 |
| 432 行 | 第 4 项「反馈 / 申诉通道」是 GitHub Issues + 用户主动导出日志，属**站外交付物**，不是该入口 |
| 86 / 407 / 446 行 | 都只把 D2 当作「零外发」的口径论据，不构成界面落点 |

**推论一**：补登记不是「补一句话」，而是要在 7 页里找一个语义不相干的页塞一个控件，与「一屏一主行动」「语义位互不重叠」抵触；设计侧下一轮有正当理由再判不通过。

**推论二（定性必须写清）**：设计侧要求「补独立语义位，但不新增页面 / 状态类 / 机制」，字面上自洽，但**可点击控件本身是一种能力**，而 H2 写的是「不新增能力」。准确说法应是：D2 入口是**用户裁决已经产生、但 CR-003 第 5 条漏登记**的界面落点，补登记属于「补登记既有裁决」，不是「新增能力」。不把这个定性写明，H2 会被自己绕进去。

## 2. 三条解法

| | **A · 补登记** | **B · 撤入口（推荐）** | **C · 静态文本位（折中）** |
|---|---|---|---|
| 做法 | 434 行补「D2 入口 → 第 ④ 页内独立语义位」，写明产品不发起网络请求、点击由系统交浏览器、不新增页面 / 状态类 / 机制 / 能力；文案与点击后可见结果登记为设计基线待办（S-D1） | 把 D2 从「产品内入口」回退为「**产品不提供任何外部入口**」。外部地址只以纯文本出现在 README / Release 说明 / 安装指引；反馈 / 申诉仍在站外（GitHub Issues + 用户主动导出日志）。产品内零外部入口、零 `NSWorkspace` 调用 | 第 ④ 页放一行**不可点击、不调用 `NSWorkspace`** 的官方仓库 / Releases 地址纯文本（可复制），承载页指定登记为「静态文本位」而非「入口」 |
| 改动面 | 最小：434 行 + 结论文件关闭登记 | 较大，约 8–10 处措辞（以实际定位为准），全是口径 / 说明，不碰 AC 主体 / 7 页 / H2 | 中等：承载页登记一句 + 若干 D2 措辞改为「静态文本」 |
| 优点 | 最快、改动最少、不回退任何已拍板项 | **阻塞项从根上消失**（没有控件就没有承载页问题）；S-D1 自动作废；H1 更严；7 页 / 20 条 AC / §8 / H2·H3·H4 全不碰；S-D2 成为核心澄清 | 保留产品内官方来源可辨识（防 fork 的一层辅助）；仍无交互态 / 点击后可见结果，阻塞项消解 |
| 代价 / 风险 | ① 7 页里仍要硬塞；② 产品从此有「能打开外部页面」的控件，与 T4「产品自身不主动发起任何外发」形成**感知落差**（架构判技术上不成立，但 2C 用户不读 P1 口径）；③ S-1 文案债挂到设计基线；④ R2 必须走系统转交、不得用 `WKWebView` / `URLSession`，实现走样就真破 H1；⑤ 设计侧下一轮可能再判「语义位不重叠」不成立 | ① 改动面比 A 大；② **回退的是用户上一轮按推荐采纳的一格，需明示拍板**；③ 用户失去一键跳转（A1 受众本就会 watch repo，成本低） | 仍需补一句承载页登记；「显示一个不能点的网址」在 UX 上略反直觉；仿冒版同样可改这行文本，防仿冒价值有限（真正的防仿冒是签名身份 + README） |

**B 的合法性依据**：`Residue-C1-分发渠道决策材料.md` §11 与 `Residue-CR-003-C1渠道裁决与术语统一.md` 第 19 行均写明——D2 是「以『继续』授权按推荐推进、非逐项明示」，**若回退这两格，D2 / D3 / D4 及第 2 节相关条目单独作废，D1 渠道裁决不受影响**。

> **务必区分**：回退 D2 **不等于**撤回 D3（签名公证纳入首版准入）、**不等于**撤回 D4（崩溃上报默认不做）、**不等于**撤回 GitHub Releases 直发。三者都保留。

**B 需要同步的措辞位置（若拍板）**：CR-003 §1 的 D2 定义、第 2 节第 2 / 7 / 9 / 10 条；v3.1 的 86 行 P1 口径登记第三类（触发物消失，改为「产品无外部入口，该类行为不存在」）、407 行 N8、446 行 §7、451 行 P6 ⑥、432 行反馈通道补「站外 / 无界面呈现」、变更清单表第 5 / 10 条文字；C1 材料 §11 追加回退登记；结论文件 B-CR003-1 关闭登记。**`Residue-概念定义卡-v2.0-能力命名.md` 已核实不含 D2，不动。**

## 3. 推荐 B，三条理由

1. **与已锁定范围同向**：A1 受众（本就会看 Releases）、GitHub 直发、零外发、本地留档、以及「会删别人文件」的 2C 工具属性——产品内零外部入口是最强的信任姿态，连「会不会偷偷联网」的解释成本都省掉。
2. **避开第二类「承诺与判定错配」**：T4 字面「不主动发起任何外发」与 P1「窗口内连接数 = 0」本就是 CR-001 双 α 刚拆过的错配类型。A 虽经架构判技术上不成立，但在**感知层**又造一处；B 让字面承诺与用户所见完全一致。
3. **不把债留给设计基线**：设计稿目前仍是「可见的假设 / 参考基线」、未冻结、3 处待改点仅记录。A 会把「入口文案 + 点击后可见结果」再挂一笔上去；B 不新增任何界面债。

**如实说明**：B 比 A 动得多，且回退用户的一格推荐。若用户更看重「最小改动、最快冻结」，A 是同样合法的解法，决策权在用户，不代为选择。这与用户此前拍「双 α：彻底拆解」的偏好一致，但**不拿偏好当授权**。
