### Q1 三场景独立复算（只依据 M4 唯一式 `a += |F ∩ P_now − C_done|`）

| 场景 | 逐步复算 | 期望 `a` | 唯一? |
|---|---|---|---|
| 自始持有 | 扫描1：候选 c 被判阳性 → `F` 未置位；扫描2：仍阳性 → `F ∩ P_now = ∅` → `a += 0` | **0** | 唯一 |
| 间歇持有 | 扫描1 阴性 → `F` 置位，`a += \|{c} ∩ ∅\| = 0`；扫描2 阳性 → `\|{c} ∩ {c} − ∅\| = 1` → `a = 1`、`C_done = {c}`；扫描3 阳性 → `\|{c} − {c}\| = 0`；扫描4 阴性 → 0；扫描5 再阳性 → 0（已在 `C_done`） | **1**（不是 2） | 唯一 |
| 同路径重建 | c1（path `p`, birthtime `b1`）扫描1 阴性 → `F[slot1] = 1`；删 `p` 后重建 → c2（path `p`, birthtime `b2`）身份键不同 → 新槽 `slot2`、`F[slot2] = 0`、`C_done` 不含 c2；扫描2 c2 被持有 → `\|∅ − ∅\| = 0`；旧 `slot1` 因 c1 失联不入 `P_now` | **0** | 唯一 |

**三例都能从唯一式直接算出、结果唯一 → 判据「算式层」可复算。但单测不能作为「`a` 判据正确」的验收证据，缺 5 项：**

1. **8 场景清单与期望值**：§11 只写「✅ 8 场景」，没有列表 → 覆盖范围不可判、不可复算（第三方无法确认是否含上述三例）。
2. **接线层用例**：单测注入的是「已算好的 `F` / `P_now` / `C_done`」三个集合，恰好跳过最容易错的一段——从真实扫描产出这三个集合（`F` 置位时机、位槽号跨扫描稳定、`C_done` 持久化与版本作用域、四动作同一时点）。
3. **端到端用例**：真进程持有 → 两次真扫描 → 读第 ⑤ 页 ⑥ 左值。这一条 **AC-08 组 A ②′ 已承载**，§11 应指向它，而不是用「8 场景」顶替。
4. **自污染用例**：`excludePIDs` 生效（产品自己 `open()` 候选后 `a` 不变）。
5. **「跨 uid 持有」的处理判据**（见 B-01）。

## 结论

**不通过**。阻塞 9 条（B-01 ~ B-09），建议 7 条（A-01 ~ A-07）。
可判性亮点如实记录：M4 唯一式在三个关键场景（自始持有 / 间歇持有 / 同路径重建）上**可独立复算且结果唯一**；T-3 / T-5 / T-6 三条移交项可直接写成用例（T-6 需环境前置）。问题集中在「接线层证据缺失」与「判据在异常输入上两读」，不在公式本身。
