## 一、B1 · 表格行高 32pt 与 ⑤ 页 ③ 列三行文字冲突

### 事实（实测，不是推测）
| 表 | 实测行距（含 1pt 分隔线） | 换算数据行高 |
|---|---|---|
| ② 候选列表 | 66 px @2x | **32 pt** ✓ |
| ⑦ 执行记录 | 66 px @2x | **32 pt** ✓ |
| ⑤ 观察期矩阵 | 114 px @2x | **56~57 pt** ✗ |
| ⑤ 矩阵表头 | — | 32 pt |

⑤ 超出的原因可精确到代码：③ 列单元格塞了 3 行（`.ratio` 13pt + 两条时点说明 11pt×2），加上单元垂直内边距 4×2 = 8，合计 49 + 8 ≈ 57。

### 关键判断：那两行时点根本不是"行级数据"

我核了 ⑤ 页三行数据的时点说明，**三行完全相同**：「总量冻结：开轮时」/「样本冻结：报告产出时」。
也就是说它不是每一行各自的数据，而是**这一列的两个值分别在什么时点冻结**——**列级元数据**。

**逐行重复列级元数据是 B 端表格的典型缺陷**：三行数据要读三遍同样的两句话，7 行就七遍。这不是"信息密度高"，是噪音。基线 §五 ⑤ 写「③ 列两个冻结时点分行标注」，本意是「两个时点不许混在一句里」，**不是「每一行都要重复一遍」**。

所以我选「减内容」而不是「抬行高」。抬行高会把一个信息设计问题变成一个尺寸问题，问题还在，只是变高了。

### 裁定

- **裁定**：**减内容**。两个冻结时点从每个数据单元格**上移到 ⑤ 页矩阵表头该列内**，分行标注；数据单元格只保留 `.ratio` 一行。**全产品表格数据行高保持唯一一档 32 pt，②⑤⑦ 三张表全部 32 pt，不新增第二档行高。**
- **具体值**：
  - 数据行高 = **32 pt**（②⑤⑦ 全部，固定，不随内容跳动）
  - ⑤ 矩阵**表头块高 = 60 pt**（③ 列在表头内占 3 行：列名「样本 / 总量」11pt + 「总量冻结：开轮时」11pt + 「样本冻结：报告产出时」11pt；行高按 §一 的 1.3，三行 42.9 + 行间 4×2 + 上下内边距 4×2 = 58.9 → 上取整到 4 栅格 = **60**）
  - ③ 列**数据单元格内容 = 1 行**（`.ratio`，13pt）
  - 单元格垂直内边距 = 4 pt（现为 4，保持）
- **理由**（三条，一条一句）：
  1. 这两行是**列级元数据**（7 行完全相同），逐行重复是噪音，上移后不仅解决冲突，信息还更清楚——用户看一次就懂这一列怎么冻结的。
  2. 数据行统一 32 pt 后，基线「保证 7 页矩阵不跳动」的原意反而更硬：**三张表同一个数**，不存在"列表 32 / 矩阵 56"两档要靠记忆区分。
  3. 不新增行高档位 = 不新增一个需要维护、需要与 §一 对齐的数值。
- **影响面**：
  - **§一「表格行高 32 pt（固定）」保持不变**，只在同节补一句：「**表头块高不计入数据行高**；表头可因列内副标高于 32 pt，但只出现一次、不参与跳动约束。」
  - **§五 ⑤** 改为：「③ 列两个冻结时点**在该列表头内分行标注**（列名 + 两行时点说明），数据单元格只放 `.ratio`。」
  - **DAC-21** 判据改为「数据行高 = 32 pt（②⑤⑦ 全部）」，测量点从 ⑤ 的 4 条分隔线改为 ②⑦ 各 1 处 + ⑤ 表头以下 1 处；**删除"⑤ 57pt"这个既有的不通过结论**（见第五节）。
  - **DAC-22** 判据从「跨表行高一致」改为「**三表同一档 32 pt 且同表内不跳动**」，不再需要两档容差表。
  - **DAC-48** 判据从「③ 列内两时点分行」改为「**③ 列表头内两时点分行**（y 坐标不同且均在表头块内）」。
  - ⑤ 页垂直空间省下约 3 × 25 = 75 pt。
- **要程必达做什么**（落 v1.1 的四处）：
  1. `Pages.swift:333-352`：删掉 ③ 分列里 `if idx == 2 { ForEach(row.freezeNotes …) }` 这段，以及数据行 `.padding(.vertical, Tokens.Spacing.xxs)`；数据行恢复 `.frame(height: Tokens.Typography.tableRowHeight)`（**用固定高，不用 `minHeight`**）。
  2. `Pages.swift:316-328`（表头）：③ 列表头格改为 3 行 VStack（`spacing: 4`，两行副标 11pt `textSecondary`），表头容器 `.frame(height: 60)`。
  3. `PageModel.swift:149-156`：`ReportRow.freezeNotes` 字段删除；两条时点串迁到 `ReportMatrix` 常量（`static let freezeNotes = [...]`），因为它是列级、不是行级。
  4. `RootView.swift:211-251`（skeleton 数据）：三处 `freezeNotes:` 入参一并删除。

> **本条为最终口径，不带"如果"。** 如果将来出现"不同来源的冻结时点确实不同"的需求（例如某来源中途加入观察期），那是**需求变更**，走变更单把时点收回行内并抬行高，不属本期；本期一律按列级处理。

## 二、B2 · 信号色「每屏 ≤1」缺逐行状态标记的例外条款

### 实测（不是印象）
| 屏 | 信号色出现次数 | 来源拆解 |
|---|---|---|
| ① | 1 | 侧栏选中态 |
| ② | **3** | 侧栏选中 1 + 行内「可参与自动删除」徽标 **2** |
| ③ | 1 | 侧栏选中态 |
| ④ | **2** | 侧栏选中 1 + 「一键清除」按钮 1 |
| ⑤ | 1 | 侧栏选中态 |
| ⑥ | 1 | 侧栏选中态（+ 危险色 2 处，不同色相，不受此限） |
| ⑦ | **2** | 侧栏选中 1 + 行内「可恢复」徽标 1 |

**这张表暴露的真问题不是"实现乱用信号色"，而是基线规则本身写不完整**：§二 把「选中态」列为信号色合法用途，而本产品**每一页都有侧栏选中态**——于是每屏的"唯一一次"在页面还没开始工作时就已经被导航吃掉了。任何页面只要有主行动，必然违规。**这是规则的结构性缺陷，不是程必达的错。**

### 裁定

- **裁定**：把「每屏最多一次」从一条**计数规则**改写成一条**优先级规则 + 一份永久排除清单**。信号色的唯一名额仍然只有一个，只回答"给谁"，不再需要"数几次"。
- **具体值 / 形态**：

  **(1) 优先级（每屏只兑现优先级最高的一个，其余全部退到中性表达）**

  | 优先级 | 承载物 | 说明 |
  |---|---|---|
  | 1 | **主行动按钮** | 每屏最多一个可执行主按钮（提交/确认/清除） |
  | 2 | **焦点环** | 键盘焦点，且仅当该屏无主行动时 |
  | 3 | **选中态** | 侧栏/分段控件当前项，且仅当该屏无主行动、无焦点环时 |

  （2）**逐行属性标记永久不进入信号色**。这不是"给逐行标记开例外"，而是**明确它不属于信号色的合法用途**——稀缺性一点没让。
  
  逐行标记的合法形态（三处一致）：

  | 项 | 值 |
  |---|---|
  | 底色 | `textSecondary` @ **12%** |
  | 文字色 | `textSecondary`（`#8B9099`） |
  | 圆角 | `radius.badge` = 4 pt |
  | 文字 | 11 pt（`typography.secondary`） |
  | 内边距 | 水平 8 / 垂直 **4**（现为 2，违反 4 栅格，一并修） |
  | 图标 | **9 pt**（新增 token `icon.size.badge = 9`），图标与文字间距 4 pt |
  | 整体高度 | 14.5 + 4×2 ≈ **22.5 pt**，在 32 pt 行高内居中，不撑行 |

  **(3) 图标位分配（五个标签，五个不同图标，不得复用）**

  | 标签 | 出现页 | SF Symbol | 语义 |
  |---|---|---|---|
  | 可参与自动删除 | ② | `bolt.circle` | 「会被自动执行」——动作性 |
  | 仅报告 | ② | `doc.text` | 「只记录不动作」——记录性 |
  | 可恢复 | ⑦ | `arrow.uturn.backward` | 「可回转」 |
  | 已恢复 | ⑦ | `checkmark.circle` | 「回转已完成」 |
  | 已阻断 | ⑦ | `slash.circle` | 「回转被拦」 |

  **(4) 可辨性兜底（防止"降级成灰字就完事"）**：灰色徽标必须在 11 pt 下可读——文字与徽标底对比度 **≥ 4.5:1**。核算：`#8B9099` on `#8B9099`@12% over `#16191F`（= `#242830`）**实测 4.65:1，仅高于门槛 0.15**。这个余量很薄，所以本项**必须实测复验**（见「若我错了」B2）；**字符不截断、不用省略号**；徽标底不得低于 12%（再低就不达标）。

- **理由**（三条）：
  1. 优先级规则把"数次数"变成"取最高一个"，判定从"数"变成"看"，**R3.8 不用再数连通域就能判**，实现方也不会再"这里多一次但那里少一次"。
  2. 侧栏选中态退到中性（`surface` 高亮 + `textPrimary` 文字）后，唯一名额真正留给主行动——④ 页立刻从 2 次回到 1 次，且这 1 次落在该页唯一的主按钮上，**语义正确**。
  3. 逐行标记用「图标 + 次文字色」表达，是靠**形状**区分而不是靠**颜色稀缺**区分——这正是 §二 自己写的「七态靠图标与文案区分，不靠颜色堆叠」的同一条原则，只是当初没贯彻到行内标记上。
- **影响面**：
  - **§二 规则**改写为优先级 + 排除清单两段（原文「一个界面上信号色最多出现一次（主行动或焦点，二选一）」保留为结论句）。
  - **DAC-25** 判据改为「信号色出现次数 = 该屏优先级最高的那一个，且为 1」，测量从"计数"改为"定位归属"。
  - **DAC-26** 保留（信号色承载物必须是主行动/焦点/选中态之一，且符合优先级）。
  - **DAC-08** 不变（灰 + 透明度仍在 6 色内）。
  - 板面影响：`ParticipationBadge`、`EvidenceBadge`、侧栏 `NavRow` / RenderWrapper 侧栏选中 4 处。
  - ⑤ 页不受影响（矩阵无选中态）；若后续给矩阵加选中行，按优先级 3 处理，届时主行动让位——**此条不在本期**。
- **要程必达做什么**（落 v1.1 的四处 + 两个 token）：
  1. `DesignTokens.swift`：新增 `Tokens.Icon.badge: CGFloat = 9`；`Tokens.Color.badgeFill` 不新增（用 `textSecondary.opacity(0.12)` 现算）。
  2. `Pages.swift:131-145`（`ParticipationBadge`）：`participation.isSignal` 分支删除，改 `bolt.circle` / `doc.text` + `textSecondary`；垂直内边距 2 → 4。
  3. `Pages.swift:522-536`（`EvidenceBadge`）：`label.usesSignal` 分支删除，按上表三个图标 + `textSecondary`；垂直内边距 2 → 4。
  4. `PageModel.swift:143-147 / 177-181`：`CandidateParticipation.isSignal` 与 `EvidenceLabel.usesSignal` 两个属性**删除**（它们的存在本身就是"允许逐行用信号色"的入口，留着下次还会被用）。
  5. `RootView.swift:151-155` 与 `PageRenderer.swift:100-103`（侧栏选中）：`signal.opacity(0.16)` → `textPrimary.opacity(0.08)`，文字色仍为 `textPrimary`。
  6. `RootView.swift:96-102`（页头「清理…」按钮）：`.borderedProminent` 去掉，改 `PrimaryButtonStyle`（这也顺手关掉我报的 C5）。

## 三、A1 · 「并发冲突」「超时」两态的落点

- **裁定**：
  - **并发冲突 → 全局页级状态条**（组件 `StatusBar`），位置固定：**页头分隔线下方、内容区最顶部、通栏**。它是**跨页共用组件**，任何页只要撞上另一实例占用的锁就显示在该页顶部，**不弹窗、不遮挡内容**。① 页是最常出现它的页面（扫描/清理是撞锁高发动作），但**它不只属于 ① 页**。
  - **超时 → ① 页内容区**（扫描超时），形态 = 内容区居中的「已超时 + 可续扫」+ 一个「继续扫描」次要按钮。**只落 ① 页**：扫描是全产品唯一的长时间任务。
- **具体值**：状态条 = `surface` 底 + `radius.control`(6) + 上下内边距 8 / 左右 12 + 一条 11 pt 中性文案 + `arrow.triangle.branch` 图标（9 pt）。位置 y 固定于页头分隔线 + 8 pt。
- **理由**：并发冲突是**运行态**（随时可能来、随时可能走），必须非阻塞且位置可预期；超时是**任务终态**（扫描结束的一种），属于内容区结论，不该占页级位置。
- **影响面**：DAC-30 有了 ①（状态条）与 ①（超时）两个具体落点；DAC-35（超限行内）仍无落点，另议。① 页 `statusSlot` 需要能同时表达"有内容"与"无冲突"（无冲突时不渲染整条，不显示空条）。
- **要程必达做什么**：`Pages.swift:33-35` 状态条逻辑保持；`OverviewPage` 增加 `timeout` 分支（`model.scanTimedOut` + 「继续扫描」动作），或在 `loading` 与内容之间插入 `.timeout` 态。`StatusBar` 无需跨页改造——它已经是独立组件，只要各页在顶部给它留位。

> **附：其余四态落点建议（非裁定，需程必达确认落点存在）**
> | 态 | 建议落点 |
> |---|---|
> | 空 | ② 候选为空 / ⑦ 无记录 / ① 未扫描过 —— 三处内容区居中，均已实现 |
> | 错误 | ① 扫描失败（`E-xxx` + 可执行动作）；**当前 `ErrorStateView` 零挂载**，必须至少挂 ① 一处 |
> | 无权限 | ④ 页（读目录需授权）+ ② 页（读候选需授权），文案补「所缺权限名 + 授权指引条目 ID」 |
> | 超限 | ③ 页表单字段触顶时行内提示（阈值上限 5 GB / 来源 10% 取小） |
> | 只读 | 全页顶部固定条（已实现），⑤ 页另加「只读，不结算」 |

## 四、A3 · ⑤ 页「③ 列两个冻结时点」同列两行 还是 两列各一个

- **裁定**：**同一列内两行，不拆列。**（落在哪两行：按 B1 已上移到该列**表头**内。）
- **具体值**：见 B1 表头 60 pt 规格；③ 列仍是**一列**，列宽 150 pt 不变。
- **理由**：
  1. 「样本 / 总量」是一个 `.ratio` **成对值**，两个时点分别修饰这两个值——拆成两列会把成对语义切散，读者要在两列间自己配对，正是 §四「界面不做算术/不做推断」想避免的。
  2. 矩阵已有 7 列，实测列宽合计 700 pt，可用宽约 775 pt，**只剩 75 pt 余量**；再拆一列（建议 90 pt）必然溢出截断。
- **影响面**：DAC-48 判据 = 表头块内两行（y 不同、同列、同容器）；列宽表不变。
- **要程必达做什么**：无需拆列；随 B1 的第 2 步一起做（表头 3 行）。

## 五、A2 · ⑥ 是抽屉还是独立页（**建议，需产品确认，我不拍板**）

- **我的建议**：**⑥ 不是第 7 个页面，是「② 页主行动触发的中断式确认抽屉（sheet）」，不占「7 页」名额。**
- **具体值**：抽屉宽 ≥ 380 pt、最小高 260 pt（沿用现值），右下角动作区 `取消`（次要）+ `移入废纸篓`（危险色），抽屉内不做页面级导航。
- **理由**：⑥ 的存在前提是"用户已选中了条目"——没有选中时它是一个**没有意义的空页面**（要么显示一句"请先选择条目"，要么全禁用）。把它做成独立页，等于逼基线为一个天然从属的确认动作造一套空态/无选中态；做成抽屉，它继承触发页的上下文（选中的条目就是它要确认的那些），这是中断式确认的正确形态。
- **影响面（如果按建议落）**：PRD「7 页 × 1 形态 = 7 ≤ 8」的口径需改为「**6 页 × 1 形态 + 1 个抽屉形态 = 7**」；⑥ 的验收标准从"页面"改为"抽屉"，但内容三要素（不可逆提示 / 条目数 / 字节 / 危险色按钮）不变。
- **要产品确认的两件事**（请主理人转达，我不定）：
  1. **触发页是 ② 还是 ①**？我倾向 **②**（候选清单选中 → 确认移入废纸篓），① 若要给主行动则复用同一抽屉。
  2. **PRD 的「7 ≤ 8」是不是有编号的验收标准**？若是硬指标，那要改的是 **PRD 的表述**，不是把抽屉硬做成页面——**形态是结果，不该为了凑计数反过来决定形态**。
- **若产品坚持 ⑥ 为独立页，我的接受条件是**：必须同时给出「未选中任何条目」的空态设计（文案 + 下一步动作），否则第 7 页会是一个永久空白页。这一条要随 v1.1 一起写进 §六「不纳入」之外，不能留白。

## 七、若我错了

> 每条一句。写这节不是客气——**裁定人给自己上保险，比事后被证明错了还嘴硬要便宜得多。**

- **B1**：如果"冻结时点是轮次级"这个前提不成立（例如某个来源中途加入观察期、两个值确实在不同轮次冻结），那表头方案就会把不同时点的数据强行标成同一时点——**这是本裁定最危险的失效方式：它不是排版错，是让人读错数据**。最可能的原因是我把 §五 的"两个冻结时点"默认读成了全表共用。
- **B2**：如果灰字徽标在 11 pt 下实测读不出来（对比度够但视觉重量太轻、列表里扫不到），那"靠形状区分"就不成立，届时正确做法是**恢复信号色但改成配额制**（如全表最多 3 个、且只标"可参与自动删除"这一种）。最可能的原因是我把"可辨"当成了二元问题，而它其实是注意力问题。**这条我有具体的心虚点：我核算的对比度是 4.65:1，只比 4.5 高 0.15，余量薄到不够掩盖任何误差——若实测复验不过，B2 的形态方案要整套重来，不能靠"再加 2% 底"糊过去。**
- **A1**：如果 ② 页分页加载、⑦ 页导出也可能超时（磁盘慢/文件多），那"超时只落 ① 页"就把两个真实超时场景逼成"无限转圈"。最可能的原因是我把扫描当成了唯一长任务。
- **A3**：如果产品要求两个时点各自可排序、可筛选、可导出成两列，那必须拆列，同列两行就挡住了后续。最可能的原因是我只按"阅读"评估，没按"操作"评估。
- **A2**：如果 PRD 的「7 页 ≤ 8」是带编号、要签字验收的硬指标，那正确动作是**改 PRD 的口径**而不是让形态迁就计数——如果这条被反过来处理（为了凑 7 页把抽屉硬做成页面），错的是裁决顺序，不是形态判断。
