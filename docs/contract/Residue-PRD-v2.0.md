### 判定口径统一定义（P1–P6、P-L0 · 供 §4 / §5 / §7 引用）

> 本节为 R1-01 / R1-04 / R1-05 / R1-06 / R1-11 / R1-14 / R1-16 的编号落点与口径统一，**不新增 AC 编号、不新增能力**。

- **P1 网络观测口径**（R1-01 / R1-04 / R1-07 / C-09）：观测对象 = 产品主进程 + 其派生的 CLI 子进程（不含系统其他进程）；过滤 = 排除回环（127.0.0.1 / ::1）、OCSP、NTP、mDNS；观测窗口 = 触发动作前 1 s 至动作结束后 5 s；「零外发」判定 = 窗口内过滤后出站连接数为 0。L1 在线自证与 CLI 能力探测如需联网，须在 N6 探测口径内（单探测 ≤ 2 s / 总 ≤ 10 s、失败按 AC-14 降级），纯本地探测不产生外发。C1 未拍板前不引入更新通道与崩溃上报。
- **P2 落盘与正文边界**（R1-04）：会话痕迹「不读正文」修订为「正文仅内存解析、只落盘包名 + 时间戳两项、正文不落盘 / 不持久化 / 不外发」。落盘载体 = N7 登记的本机单一 jsonl。包名位于会话 jsonl 正文内，文件名 / 目录名只含路径或 hash；本产品不宣称「不读正文」，只约束上述可实现的边界。
- **P3 删除调用判定**（R1-05）：「系统调用审计中删除调用数为 0」修订为「产品自身执行动作日志中，动作字段值为 `rename_to_trash`，且 `rm` / `unlink` / `unlinkat` / `rmdir` / `rename` 覆盖（枚举）调用出现次数为 0」。不依赖 dtrace / fs_usage / Endpoint Security（需 root 或特定 entitlement + 公证，与无 root 及 C1 未定不兼容）。Then 断言「不调用 rm」与判定同层级。
- **P4 状态词表**（R1-11 / C-14，互斥）：「未采集」（未授权 / 后两档默认关）、「已停止」（曾开启后关闭自动删除）、「无法判定」（权限不足 / 信息不足的独立状态，**不等于**「判定为不删」）、「L0 活引用阻断」、「L2 弱信号否决」、「二次检查阻断」。界面不混用。
- **P5 个人信息与本机元数据**（R1-06）：个人信息按**可识别性判定**，不按字段语义、也不因不外发而消失。MCP 配置路径常含用户名 / 项目名 / 私有包名 / 内部 registry，包名 + 精确时间戳序列构成行为画像 → 纳入本机治理，不新增身份类收集字段。三件套：①收集必要性（8 举证链字段逐条挂 AC、会话痕迹 2 字段挂 AC-12）；②留存期限 = **C3**（未拍板前不自动删除日志）；③删除路径 = N7 一键清除 + AC-12 随时清除。
- **P6 安全检查「全套」构成清单与承载编号**（R1-16）：①采集范围与开关首次扫描前明示（AC-11 / V3）；②后两档默认关（AC-11）；③运行时授权降级（AC-14 / N8）；④个人文件零扫描零删除（AC-07 / N5）；⑤本机可识别元数据三件套（N7 / P5）；⑥2C 对外发布责任（N8）。可观测结果 = 上述各编号的判定项均可执行。**只补编号落点，不新增 AC 编号**。
- **P-L0「持有」判据表**（R1-02）：某进程对候选路径持有 fd / 文件锁 / cwd 三者之一即为「持有」。L0 检查窗口 = 首次检查时刻 → 删除动作前二次检查时刻。FDA 未授予时无法可靠枚举别的进程 fd，产品按 AC-14 降级只读，既不报「L0 活引用阻断」也不报「无活引用」。

## 1. 问题陈述〔本节未修订〕

跑 coding agent / MCP server 的个人开发者（A1）机器上，一次性工具由 uvx / npx 拉起后把可再生的运行时缓存（~/.cache/uv 50 GiB / 328 万文件、~/.npm/_npx 14 GB 量级）永久写进全局目录且无人回收；而 npm / uv / pip / brew 只维护安装清单、不记录最后使用时间，APFS / relatime / noatime 下 atime 又普遍失真，所以「多久没用就自动删」这类工具拿不到可信的「在用」证据，也没有任何产品敢对误删负责——**病灶不是缺清理工具，是缺一条可举证的「可删」判定链**。

| 要素 | 内容 |
|---|---|
| 谁 | A1 个人开发者 / AI 重度用户 |
| 场景 | 临时用一次的工具被安装、缓存写入全局目录，之后几乎不再用 |
| 痛点 | 磁盘被静默占满，用户既看不见占用来源，也不敢手工删 |
| 现状 | 手工 `uv cache clean` / `npm cache clean --force` / `brew cleanup`，或干脆不清理 |
| 为什么不行 | 手工命令无「在用」判定、会被活着的进程持锁阻塞、无回滚、无举证、无定时 |

- 判定：按 P1 窗口内过滤后出站连接数为 0；P2 落盘载体（N7 登记的本机 jsonl）记录字段仅「包名 / 时间戳」两项、无会话正文落盘文件；清除后该档记录条数为 0（「无残留」与「记录条数为 0」口径对等，R1-04）。**本 AC 不宣称「不读正文」**（包名在正文内，技术上不成立），只约束 P2 可实现的边界

**AC-13（误删可回滚）〔修订 R1-13 连带 / C-15；C-04 部分转 Backlog〕**
- Given 一次已执行的清理，且该条目的废纸篓回滚位置仍有效

- 判定：原路径文件存在且字节数一致；日志该记录含执行动作与 L0 检查时刻（时限见 C3，未拍板前不对外宣称）；「回滚位置有效性」= 废纸篓中该条目存在（R1-13 连带：为「回滚后旧判定结果复现」提供比对基准）。**「用户 / 系统清空废纸篓后回滚位置失效」异常态按 C-04 转 Backlog，登记为 Phase 2 设计异常态补充，本期不改本 AC 判定**

**AC-14（权限被拒时的降级）〔修订 R1-11 / R1-02 / C-16〕**

- 判定：磁盘文件数与字节数前后一致；受阻来源列表非空且每条「所缺权限」字段有值；**授权指引以可查文案 ID / 条目呈现**（R1-11 把「可操作的授权指引」改为可观测）；所有状态为「无法判定」（P4 独立状态词）的条目删除动作数为 0，且其状态字符串为「无法判定」而非「判定为不删」（可区分归因、不因已降级只读而恒真）；「无法判定」与「判定为不删」界面不混用（设计 B2 / C-16）

**AC-15（单次上限与条目数上限）〔修订 R1-12 / C-20 核对无异议〕**
- Given 候选总量超过 V2 注入的单次上限（待确认）；且本次执行处于「首次」或「稳定后」之一
- When 执行清理
- Then 实际删除量不超过「首次 5 GB 与来源 10% 取小」、稳定后不超过来源 20%、条目数不超过条目数上限，超出部分顺延并留痕
- 判定：Then 枚举的**三项约束（容量上限 / 条目数上限 / 顺延留痕）各有一条可观测结果**，与判定项一一对应（R1-12 消解「五项 / 三项」指代不唯一）；任一触顶即停止；日志记录「上限触顶」一次；顺延条目数 = 候选总数 − 实际删除条目数；阶段分界可观测：「首次」= 本机首次产生实际删除动作且观察期首轮，「稳定后」= 已完成 ≥ 1 次实际删除后的后续执行，同一次执行按阶段标记字段只适用一档

**AC-16（规则版本 / 灰度 / 回滚 / 更新后重计观察期）〔修订 R1-08 / R1-13 / R1-17；C-06 转 Backlog〕**

- When 规则发生更新
- Then 旧规则可回滚、观察期计时器归零、自动删除回到不可点亮状态直到重新通过 C2 合格线
- 判定：版本号字段可查且新旧不同；「回滚后旧判定结果复现」以「旧规则版本号 + 回滚前该规则下的举证链判定结果」为比对基准，回滚后同一样本条目判定结果与基准一致（R1-13 补基准）；观察期天数计数为 0；开关状态为 disabled；**「可灰度」可观测结果 = 灰度状态字段可查且取值 ∈ {未灰度 / 灰度中 / 全量}，更新后初始为「未灰度」**（R1-13）；**承载页：版本列表 / 回滚动作 / 灰度状态三项由既有第 ⑦ 页承载，不新增页面，7 页 × 1 形态 = 7 ≤ 8**（R1-13 / C-11，7+2=9 超限方案不采纳）；正向路径：观察期重新计时并达 C2 注入合格线后，按 AC-08 组 B 可再次点亮（R1-08 / R1-17：与 S2「错 1 次永久锁死」按「规则版本号」区分状态，见 S2 修订）。**应用自身版本升级的数据模型 / 迁移 / 回滚脚本按 C-06 转 Backlog，N9「可回滚」本期仍只覆盖规则、不扩到数据**

**AC-17（L0 的 TOCTOU 窗口）〔修订 R1-02 / R1-14 / C-16〕**

- When 到达删除动作
- Then 删除前 L0 二次检查发现活引用并放弃该条目
- 判定：该条目仍在原位且字节数一致、日志原因字符串为「二次检查阻断」；「L0 检查时刻」字段按 V4 修订口径存放「首次检查时刻 / 二次检查时刻」两个子值且互不相同（R1-14：该字段为含两个子值的复合顶层字段，计数仍按 8 个顶层字段、子值不计入分母）。**能力边界：用户态二次检查只能缩小 TOCTOU 窗口、不能消除**（N5 已删「覆盖 TOCTOU」，R1-02）

**AC-18（举证链字段完整）〔修订 R1-14 / C-07 / C-15〕**
- Given 任一候选被评估
- When 打开其举证详情
- Then V4 的 8 个顶层字段全部有值或显式标注「不适用 + 原因」，无空白、无「以后再补」

**AC-19（定时任务的上游能力边界）〔修订 C-09 口径 / C-17 承载页；B-01 原样标注〕**
- Given 配置定时任务
- When 选择上游能力
- Then 可执行集合仅含 `uv cache prune`、`brew cleanup --prune`、`npm cache clean --force`、`pipx` 临时 venv 过期、`trash-put`、`z-clean audit` 只读审计，且不含 `uv cache clean`
- 判定：任务配置与执行日志中 `uv cache clean` 出现次数为 0、集合外命令数为 0；定时任务配置承载页 = 第 ③ 页「清理策略配置」（C-17，不新增页面、7 页复核不变）；CLI 探测联网口径按 P1 / N6（C-09）
- **B-01 待用户裁决标注（本轮不改本条、不替用户选）**：集合中 `uv cache prune` / `brew cleanup --prune` / `npm cache clean --force` / pipx 过期清理为上游直接删文件、不进废纸篓、无「回滚位置」，与 N5 / AC-13 / 核心功能 C3 冲突；`trash-put` 非 macOS 原生、`z-clean audit` 全文无定义；「pipx 临时 venv 过期」是行为描述、粒度不齐；集合不含 `uv cache dir` / `npm config get cache` / `brew --cache` 等只读定位命令，而「集合外命令数为 0」会禁止 AC-01 与 L1 所需的它们。以上按 **B-01 原样登记为「升级用户裁决」**，PM 不自行修改

**AC-20（扫描成本预算）〔修订 R1-15 / C-01 / C-02〕**

- Then 默认走增量、可随时取消、断点可续，满足 N1/N2/N3 的时长与 CPU/电量预算，电池供电且电量低于 20% 时暂停
- 判定：取消动作后 5 秒内无新增扫描 I/O（「扫描 I/O」= 产品进程对目标目录发起的 stat/readdir/getattr 调用；5 秒起点 = 取消指令被产品接收时刻；在途 I/O 允许在窗口内完成、窗口结束后无新增，R1-15 定义三处）；**重启后可续扫结果断言**：重启后从断点续扫并最终产出的报告与未中断扫描报告在「文件数 / 字节数 / 候选清单」三项一致；N1/N2/N3 三项指标超标项数为 0（与 S5 口径统一见 §9）；低电量时段任务执行次数为 0；N4「单次执行超时」的自动整体回滚与 AC-13 手动逐条回滚为两条独立路径（C-02）；N4「执行」不含扫描（扫描时长归 N1 的 10 min，避免冲突，R1-15）

### B-01 · 上游能力边界（范围 / 能力边界选择，只能用户拍板）

**问题**：`uv cache prune` / `brew cleanup --prune` / `npm cache clean --force` / pipx 过期清理都是上游直接删文件、不进废纸篓、无「回滚位置」，与 N5「一律原子 rename 到废纸篓、禁止 rm」、AC-13「从废纸篓恢复」、核心功能 C3「删得掉且收得回」正面冲突。另：`trash-put` 非 macOS 原生（第三方 trash-cli），2C 不能假设已装；`z-clean audit` 全文无定义；「pipx 临时 venv 过期」是行为描述、与其余命令粒度不齐；集合不含 `uv cache dir` / `npm config get cache` / `brew --cache` 等只读定位命令，而「集合外命令数为 0」恰会禁止 AC-01 与 L1 所需的它们。**直接冲击安全底线「可回滚 / 后悔期」。**

| 选项 | 做法 | 代价 |
|---|---|---|
| ① | 上游只做只读探测与举证，删除全由产品自己按 N5 执行 | 保住可回滚；但失去 `uv cache prune` 的可达性剪枝能力，产品须自研可达性判定，**工程量与误判风险显著上升** |
| ② | 承认上游 prune 是不可回滚的真删除，单列为高风险执行方式、默认禁用、用户显式选择才启用 | 保住能力；但「删得掉且收得回」**对外不再成立** |

**范围决策变更单提示**：选项 ② 与已锁定决策 2（自动删除能力必须存在）/ 核心功能 C3「删得掉且收得回」冲突，若用户选 ②，**须先出「范围决策变更单」**，PM 不得自行变更八条决策。AC-19 / N5 本轮按原文登记、未修改。
