## 一、建模口径（先说清单位，否则下面 23 条没法核对）

| 项 | 定义 | 与「功能点」的区别 |
|---|---|---|
| **旅程** | 一个用户目标从**入口**走到**可观测终态**的完整路径 | 功能点只判「某一步对不对」；旅程判「这一串能不能串起来」 |
| **入口** | 用户**真实能点的那个东西**（某个页面上的某个控件），不是「系统内部某函数被调用」 | 入口不存在 = 旅程不存在，不管代码里有没有那个能力 |
| **出口** | **双证**：① 用户在界面上能看到的终态；② 落盘物上能核对的终态。**只有 ① 没有 ② = 假成功；只有 ② 没有 ① = 用户看不见，等于没发生** | 禁止写「执行成功」「流程正常」这类不可观测表述 |
| **中途必经节点** | 少一个就断的界面节点（不是「可能经过」） | 用于把断点定位到**步骤**，而不是笼统判「失败」 |
| **异常分支** | 该旅程在中途失败后的**走向**（不是「错误码」） | 判的是「用户还有没有出口」，不是「错误码对不对」 |

**可观测性三档（本文件每条旅程都标）**：

| 档 | 含义 | 本机（无头会话）能否验 |
|---|---|---|
| **S** | 静态渲染图上就能看到终态 | 能（看图即可，但只能看形态，不能看数值正确性——见下方警告） |
| **I** | 需要交互（点击 / 滚动 / 焦点 / 键盘）才能看到 | **不能**（无头会话，只能离屏渲染静态帧） |
| **T** | 需要 14 个日历日或系统状态注入（电量 / 磁盘满 / 断电）才能走到 | **不能**（除 §9.5 测试注入点，且注入点当前未接线） |

> **⚠ 必须先说的一条硬警告（否则下面所有 S 档都会被高估）**：R2 §24「A-9 遗留 #4」明写——**七页当前是「骨架 + 语义位占位」，尚未与真实 `Metrics` / `GateEvaluator` 接线**。因此渲染图上的 `2.4 GB` / `27 / 30` / `第 2 轮 · 观察期 5/14 天` **全是占位样例值，不是真实读数**。
> 后果：**S 档只能验「这个语义位在不在、形态对不对」，不能验「这个数算得对不对」**。任何「数值正确性」的旅程，本阶段一律降为 I/T 档。

## 四、跨端旅程（X · 1 条 · **不适用，给原因**）

| # | 旅程名 | 类型 | 入口 | 出口 | 中途必经节点 | 异常分支 | 档 |

| **X-01** | **不适用** | 跨端 | — | — | — | — | — |

**为什么这一栏是空的而不是编三条出来**：

1. **PRD §6 交付形态清单**把 PC Web / 后台 / H5 / 小程序 / iOS / Android / 鸿蒙 全部写成**「明确不做」**，唯一形态 = **macOS 原生桌面**。**交付形态 = 1 个端**，跨端一致性在定义上不成立。
2. **技术上也真的做不到多端**：浏览器沙箱读不到 `~/.cache`、调不了包管理器 CLI、无法 `rename` 到废纸篓（PRD §6 逐行给了理由）。所以这不是「本期先不做」，是「形态上不可能」。
3. **本产品的跨端替代物是「跨节点」**：同一个数在 **③ 页未达项 / ⑤ 页 ⑥ 列 / 导出报告结论式** 三处出现（R2 §12.2 明写「三处必须调用同一个 `Metrics.l0Display(a:b:)`」）。**这就是我要抓的东西**，它比跨端更脆——跨端至少是两个进程，跨节点是同一个进程里三处各拼一次字符串。
4. 因此我把「跨端一致性」这道闸门**整体平移为「跨节点同源」**，落在 `Residue-链路用例-v1.0.md` 的 LC-02 / LC-04 两处。
