# Residue · 设计验收标准 DAC v1.0

> **唯一依据**：`Residue-视觉基线-最小集-v1.0.md`。
> **撰写方式声明（必须保留）**：本 DAC **在七页实现完成之后补写**，撰写时**未查看任何渲染图、未阅读任何 SwiftUI 源码**（仅依据视觉基线原文）。即便如此，它仍存在「按现状合理化」的结构性风险——不是因为我看了实现，而是因为我**知道实现已经存在**，在拿不准的地方容易下意识往「已经能做到的」方向写。
> **建议**：完整 R1.5 设计基线落地后，本 DAC 必须重新审定一次（v2.0），并把增补项一次并入。
> **本 DAC 的性质**：它不是完整设计验收标准。视觉基线本身只定了四件事（排版刻度 / 两档语义色 / 八态视觉映射 / 语义位类型化）+ 七页骨架约束，**没有逐字文案、没有完整八态视觉映射、没有深色/浅色、没有动效**。所以本 DAC 的覆盖上限就是视觉基线的覆盖上限——基线没写的，这里不能凭空立标，否则就是我在走查现场给自己造打回权。
> **基线 → DAC 的映射完整性自检**：视觉基线 §一～§五 的每一条约束，本 DAC 都有一条对应（见「依据」列）；未对应的只有 §六「明确不做」五项，单列在「本期不纳入 DAC 的项」。

## 零、术语与计数口径（先定义，否则下面半数条目不可判定）

| 术语 | 定义 |
|---|---|
| **屏** | 一个页面的静态渲染画面（ScrollView 内的不可见部分**计入**同一屏）。打开的抽屉 / 弹层视为**独立一屏**，不与被其覆盖的页面合并计数。 |
| **信号色出现次数** | 同一屏内，`#5E6AD2` 的**独立可见着色区域**数。一个按钮（含其文字与底）= 1 次；一个焦点环 = 1 次；一个进度环 = 1 次；同一控件内的图标与文字同色视为 1 次。半透明信号色按「是否可辨识为该色相」计入。 |
| **危险色出现次数** | 同上口径，色值 `#D9534F`。 |
| **token 取值** | 以 `Sources/ResidueApp/DesignTokens.swift` 中的字面量为准；若 token 被引用而未定义字面量，视为**无法判定**，记「证据不足」，不计通过也不计不通过。 |
| **视觉实测** | 以 `design-renders/*.png`（2000×1280，2× 渲染）取色 / 测量，数值换算回 pt（÷2）。 |
| **判定档位** | 只有「通过 / 不通过」两档。不存在「基本还原」「差一点」。 |

**双源规则**：token 与视觉实测**不一致时**，两者都记不通过——token 对而渲染错，说明 token 没被用上；渲染对而 token 错，说明下一个页面会错。

## 七、信号色与危险色的使用次数约束（视觉基线最硬的规则）

## 基线缺口（视觉基线本身的缺口，我在补 DAC 与走查过程中确认的）

> 这一节是给主理人的核心结论：**最小集只有四项，撑不住一次完整走查**。以下缺口不是工程问题，是基线问题。

| # | 缺口 | 严重度 | 为什么必须补 |
|---|---|---|---|
| **B1** | **§一「表格行高 32 pt 固定」与 §五 ⑤「③ 列两个冻结时点分行标注」数学上冲突** | **高（已造成 1 组不通过）** | 13 pt + 11 pt + 11 pt + 行距 ≈ 38~40 pt，32 pt 装不下。基线要么抬矩阵行高（建议 56 pt）、要么改 ③ 列表达。**这条不裁定，DAC-21/22 永久不可能通过** |
| **B2** | **§二「信号色每屏最多一次」没有给「逐行状态标记」的例外条款** | **高（已造成 2 条不通过）** | 「可参与自动删除 / 仅报告」「可恢复 / 已恢复 / 已阻断」都是**逐行属性**，一个列表天然会有 N 个。按字面读，任何逐行着色都违规；但产品语义上这些标记又必须可辨。基线必须给合法表达（建议：改用图标位 + 次文字色，把 signal 完全让给主行动） |

| **B6** | **无断点 / 窗口极值规则** | 中 | macOS 窗口可缩放（`minWidth: 900`），基线未给最窄/最宽约束 → 无法验极值稿，窄窗口下列宽 700 pt 的矩阵是否截断无从判断 |
| **B7** | **无控件最小尺寸 / 触达区** | 中 | 开关 34×19 pt、徽标高 10.5 pt — 桌面端尚可，但基线没有数字，无法判定「是否过小」 |
| **B8** | **无焦点态 / 键盘可达规格** | 中 | §二 把「焦点环」列为信号色合法用途，却从未定义焦点环样式 → 五处「信号色二选一」里的「焦点」一侧根本没有实现依据 |
