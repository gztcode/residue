## 首版范围收窄声明（CR-009 · 唯一优先级高于后续所有小节的约束）

> **为什么收窄**：v3.4 → v3.9 六轮三方复核，阻塞 16 → 27 → 18 → 14 → 13 → 15，未收敛。根因不是文字，是**九个维度两两耦合**（判定域 × 快照 × 门槛 × 失联 × L2 × 熔断 × 版本键 × 结算态 × 留存豁免）——散文无法把它们约束成一致。证据：`K = T − J` 在观察期内不可得、`inode/birthtime` 判据与「同名重建」同输入两归，这两条是**机制问题**，改文字修不掉。
>
> **收窄原则**：拿掉**产生矛盾最多的维度**，而不是拿掉不重要的功能。被拿掉的部分条文一律保留（H4 历史留痕），但**标注「本期不交付」、移出本期验收范围**。

### 收窄带来的一个直接后果（必须写明）

**「错 1 次永久不允许点亮」的「永久」边界变了。** 原本靠「规则版本切换重置」，AC-16 不交付后该边界消失 → 改为：**「永久」= 当前应用版本内永久；应用更新后 L0 计数与观察期一并重置**（沿用 CR-007 已登记的副作用「产品方频繁发版会稀释记录」，本版接受）。**这不是新增机制，是把原本挂在「规则版本」上的边界改挂到「应用版本」上。**

## 1. 问题陈述〔本节未修订，v3.0 逐字保留〕

跑 coding agent / MCP server 的个人开发者（A1）机器上，一次性工具由 uvx / npx 拉起后把可再生的运行时缓存（~/.cache/uv 50 GiB / 328 万文件、~/.npm/_npx 14 GB 量级）永久写进全局目录且无人回收；而 npm / uv / pip / brew 只维护安装清单、不记录最后使用时间，APFS / relatime / noatime 下 atime 又普遍失真，所以「多久没用就自动删」这类工具拿不到可信的「在用」证据，也没有任何产品敢对误删负责——**病灶不是缺清理工具，是缺一条可举证的「可删」判定链**。

| 要素 | 内容 |
|---|---|
| 谁 | A1 个人开发者 / AI 重度用户 |
| 场景 | 临时用一次的工具被安装、缓存写入全局目录，之后几乎不再用 |
| 痛点 | 磁盘被静默占满，用户既看不见占用来源，也不敢手工删 |
| 现状 | 手工 `uv cache clean` / `npm cache clean --force` / `brew cleanup`，或干脆不清理 |
| 为什么不行 | 手工命令无「在用」判定、会被活着的进程持锁阻塞、无回滚、无举证、无定时 |

## 观察期判定与归零规则（CR-006 · K-6 / CR-008 · A′ 路线 · 定义性小节，**不新增 AC 编号 / 不新增状态类**）

> 起因：观察期「归零 + disabled」有三个写入口——AC-16 组 A（规则更新）、AC-16 组 B（用户退回规则版本）、AC-08（熔断回退）。原契约无仲裁规则、无版本守卫，会产生双重归零与竞态（架构复核 B4）。

| 规则 | 内容 |
|---|---|
| **单写入口** | 观察期状态与开关状态由**同一状态写入口**维护；三个触发源只**提交归零请求**，不各自直接写状态 |
| **版本号守卫** | 每次归零记录**触发时的规则版本号**；仅当**当前生效版本 = 触发时版本**时，该归零请求才生效。旧版本窗口内产生的恢复事件**不得打回**新版本；**凡导致版本切换的归零请求，触发时版本一律记为切换生效后的版本**——规则更新路径记为更新后的 N（若按字面记为 N-1、而生效版本已切到 N，该请求会被守卫拒掉，AC-16 组 A「观察期天数计数 = 0」即不可满足，CR-007 · 架构 S-1）；**U1 退回路径为同型自反**（记为切换后的 N-1，否则组 B「观察期天数计数 = 0」同样不可满足，CR-008 · G-12），判定见 AC-16 组 B |
| **归零语义** | **归零 = 观察期计时器清零 + 样本计数清零 + L2 误判分子清零 + 失联计数清零**，四者必须同时发生（只清计时器不清样本 → 「窗口已重置、分子分母仍是旧值」；只清分母不清 L2 分子 → **分子 > 分母**，直接违反 AC-09 「分子 ≤ 分母」）。**L2 分母为窗口派生量**（= 该来源本观察期被判「可删」的条目数，随报告载体一并失效），故**不列入四清、也不单列**——归零后分子与分母同为 0，AC-09「分子 ≤ 分母」自然成立（CR-008 · 补 架构 S-5 / 质量 W-2）。**L0 误判计数不随归零清零**：它只在**规则版本切换**（AC-16 组 A）时随版本重置，同版本内的**熔断回退保留 L0 计数**——即 S2「错 1 次永久不允许点亮」的「永久」= **该规则版本内永久**（CR-007 · R-5 / 待裁 1）。**〔CR-008 · G-12 修正〕删「U1 退回保留 L0」**：U1 退回本身就是 N → N−1 的版本切换，L0 必须按 (来源, N−1) 键取值，与「计数第一键·跨版本不混算」自洽 |
| **幂等** | 同一版本下重复提交归零请求，结果与提交一次相同 |
| **可观测** | 归零后：开关 = disabled、天数计数 = 0、样本计数 = 0；三个触发源各自的**原因文案不同**，但状态字段与判定项相同 |
