## 1. 问题陈述

跑 coding agent / MCP server 的个人开发者（A1）机器上，一次性工具由 uvx / npx 拉起后把可再生的运行时缓存（~/.cache/uv 50 GiB / 328 万文件、~/.npm/_npx 14 GB 量级）永久写进全局目录且无人回收；而 npm / uv / pip / brew 只维护安装清单、不记录最后使用时间，APFS / relatime / noatime 下 atime 又普遍失真，所以「多久没用就自动删」这类工具拿不到可信的「在用」证据，也没有任何产品敢对误删负责——**病灶不是缺清理工具，是缺一条可举证的「可删」判定链**。

| 要素 | 内容 |
|---|---|
| 谁 | A1 个人开发者 / AI 重度用户 |
| 场景 | 临时用一次的工具被安装、缓存写入全局目录，之后几乎不再用 |
| 痛点 | 磁盘被静默占满，用户既看不见占用来源，也不敢手工删 |
| 现状 | 手工 `uv cache clean` / `npm cache clean --force` / `brew cleanup`，或干脆不清理 |
| 为什么不行 | 手工命令无「在用」判定、会被活着的进程持锁阻塞、无回滚、无举证、无定时 |

## 2. 范围

**做什么**：只读扫描与存储总览 → L0-L3 证据链判定（L2 只否决）→ 影子观察期举证 → 用户显式启用后在严格上限内原子移入废纸篓 → 全程日志与可回滚。

**核心功能 3 个**：C1「看得见」、C2「判得准」、C3「删得掉且收得回」。

**八条已锁定范围决策**：① 对外发布 2C；② 自动删除能力必须存在、用户可不启用；③ 第一版受众 A1（A2 第二阶段、A3 逻辑不成立）；④ 加入产品自己的 L2 弱感知层；⑤ L2 四档信号全部实现；⑥ 分层默认 + 关闭自动删除时所有采集停止且界面可见可验；⑦ L2 只有否决权、没有许可权；⑧ 只清可再生物料。

**明确不做（本期）**

| 项 | 为什么不做 |
|---|---|
| A2 团队 / 企业 IT 与控制面服务 | 需改架构为带控制面的服务，本期是单机 2C |
| A3 普通 Mac 用户 | 这类机器上不存在该病灶，逻辑不成立 |
| 扫描或删除任何个人文件 | 事实约束硬边界 |
| 清理源码 / 日志 / 用户数据等非可再生物料 | 决策 8 |
| 以「最后使用时间 / atime」为判定依据 | 包管理器不记录、atime 失真 |
| 用 L2 弱信号单独证明「可删」 | 决策 7 |
| 把 `uv cache clean` 等会被活进程持锁阻塞的命令放进定时任务 | 会卡住 cron |
| Linux / Windows / Web / 移动 / 小程序 / 后台 / H5 形态 | 首版聚焦单一形态 |
| 账号体系 / 云同步 / 遥测 / 崩溃上报 / 付费 | 渠道与对外承诺未拍板前不引入任何外发 |
| 修改或冻结现有 Ardot 设计稿 | 用户明确保留 |
| 「支持多种 / 灵活配置 / 可扩展」类抽象 | 无第二个真实场景，且不可验收 |

## 3. RICE 排序

口径：Reach = 每 100 位首版 A1 用户中每周该能力可见或可用的数量；Impact 取 3/2/1/0.5/0.25；**无用户直接证据的功能 Confidence 一律记 50%**；Effort 单位人日；Score = (R×I×C)/E。

| 排序 | 功能 | R | I | C | E | Score | 本期做? |
|---|---|---|---|---|---|---|---|
| 1 | 只读存储总览 | 100 | 2 | 100% | 8 | 25.0 | 是 |
| 2 | 各环境占用可视化 | 100 | 2 | 100% | 10 | 20.0 | 是 |
| 3 | 清理策略配置 | 90 | 2 | 100% | 12 | 15.0 | 是 |
| 4 | 授权与隐私交互 | 100 | 2 | 100% | 15 | 13.3 | 是 |
| 5 | 白名单与保护规则 | 70 | 3 | 50% | 10 | 10.5 | 是 |
| 6 | 自动删除引擎 | 70 | 3 | 100% | 25 | 8.4 | **是（例外）** |
| 7 | L0-L3 证据链 | 70 | 3 | 100% | 30 | 7.0 | 是 |
| 8 | 举证链与执行日志 | 70 | 2 | 50% | 12 | 5.8 | 是 |
| 9 | 影子观察期 | 70 | 2 | 50% | 15 | 4.7 | 是 |

**排序例外声明**：F6 自动删除引擎 RICE 排第 6，但决策 2 是用户拍板的产品准入条件，**不参与 RICE 的「本期做?」裁决**；低 ROI 风险在此记录，不阻挠。F7/F9 分数低但属主链路必要组成，不转 Backlog。Confidence 50% 的 3 项须在观察期用真实数据回补。

## 4. 验收标准（Given/When/Then · AC-01 ~ AC-20）

所有 `[Vx]` 以配置注入执行且标注待确认；所有 `[Cx]` 由用户拍板后注入、PM 不代填。

**AC-01（正常路径 · 只读扫描）**
- Given 已安装并完成前两档首次扫描授权，自动删除保持默认关
- When 用户触发一次扫描
- Then 产出只读报告（各来源占用量 / 可再生物料清单 / 不可再生物料清单），磁盘上无任何文件被修改或删除、无网络请求发出；判定：目标目录文件数与字节数前后一致、抓包外发请求数为 0、报告三个区块均非空

**AC-02（L1 确定值与 L2 推断值分列）**
- Given 扫描完成且存在 L2 推断值
- When 打开存储总览
- Then 「确定可释放（L1）」与「推断可释放（L2）」显示为两个独立数字，推断值带「推断 · 不作为删除依据」标识且不并入可删除量；判定：界面可分别读出两个数值，且可删除量数值等于 L1 值

**AC-03（清理策略配置默认值）**
- Given 首次启动
- When 打开清理策略配置
- Then 自动删除开关为「关闭」、执行方式为「仅报告」、单次上限与条目数上限可见可编辑、白名单可增删且保存后生效；判定：三项默认值唯一，白名单新增条目在下次候选生成中不再出现

**AC-04（正常删除全链路）**
- Given 用户已启用自动删除、观察期已通过 C2 注入的合格线，某候选同时满足「L0 无活引用 + 属可再生物料 + 观察期通过 + 在 V2 上限内 + 未被白名单或弱信号排除」
- When 到达定时执行点
- Then 该候选被原子 rename 到废纸篓（V5 待确认），不调用 rm，执行动作与回滚位置写入举证链；判定：源路径不存在、废纸篓出现同名条目且字节数一致、日志动作字段值为 rename、系统调用审计中删除调用数为 0

**AC-05（L0 活引用阻断）**
- Given 候选项被活着的 MCP server / 进程持有，或由上游可达性判定为在用
- When 执行清理
- Then 该条目不进入删除队列，报告标注「L0 活引用阻断」并写入 L1 结论与 L0 检查时刻；判定：条目仍在原位且字节数与 mtime 不变、报告原因字符串为「L0 活引用阻断」、举证链两字段均非空

**AC-06（L2 弱信号否决 / L2 只有否决权）**
- Given 两个候选：A 为 L0 通过但 L2 任一信号显示可能仍在用或命中白名单；B 为 L0 未通过但 L2 四档信号均无使用迹象
- When 执行一次清理
- Then A 与 B 均不进入删除队列，A 记「L2 弱信号否决」、B 记「L0 活引用阻断」；判定：两条目仍在原位且字节数不变，日志两条原因分别为上述两个字符串

**AC-07（非可再生料 / 个人文件排除）**
- Given 扫描范围内含源码、日志、用户数据及任意个人文件
- When 生成候选清单
- Then 上述条目均不出现在候选清单中，扫描不读取其内容、不删除；判定：候选清单条目全部属于缓存 / 临时 venv / 构建产物三类，个人文件字节数与 mtime 前后一致，内容读取记录数为 0

**AC-08（观察期未通过不得开启自动删除）**
- Given 观察期未满 V1 注入天数，或误判率未达 C2 用户拍板后注入的合格线
- When 用户尝试点亮自动删除开关
- Then 开关保持不可用并展示未达项与观察期剩余天数；判定：开关状态为 disabled，且对任意注入的合格线数值该行为一致（本 AC 只验「未达线即不可点亮」，不验阈值本身）

**AC-09（影子观察期报告与误判原料）**
- Given 处于影子观察期内（V1 待确认）
- When 观察期结束生成报告
- Then 报告只含建议、不执行任何删除，且对每个被判「可删」条目记录「后续是否被重新用到」及重新下载 / 同名条目重建情况；判定：磁盘文件数与字节数前后一致、报告「后续是否被重新用到」字段填充率 100%

**AC-10（关闭自动删除后所有采集停止）**
- Given 四档采集曾全部开启、用户曾启用过自动删除
- When 用户关闭自动删除
- Then 四档信号采集全部停止、常驻监听进程退出、界面四档状态逐一显示「已停止」且可验；判定：四档状态位均为「已停止」、无常驻事件监听进程、关闭后 60 秒内新增采集日志条数为 0

**AC-11（分层默认 + 独立授权 + L2 四档全实现）**
- Given 首次进入授权流程，且四档均已完成各自授权
- When 用户查看授权流程并执行一次扫描
- Then 前两档默认开且仅一次授权，后两档各自默认关且各有独立开关与独立授权文案，常驻采样页明示资源占用，举证链四组信号位均有取值，任一档未授权时该组为「未采集」而非空值或推断值；判定：默认值唯一（开/开/关/关）、四组信号位可分别读取、未授权组状态字符串为「未采集」

**AC-12（agent 会话痕迹采集边界）**
- Given 用户开启 agent 会话痕迹档
- When 采集发生且用户随后点击「随时清除」
- Then 采集仅记录包名与时间戳，不读取正文、不上报、不持久化会话内容，清除后本机无该档残留；判定：抓包外发请求数为 0、落盘记录字段仅两项、清除后该档记录条数为 0

**AC-13（误删可回滚）**
- Given 一次已执行的清理
- When 用户在恢复入口选择某条执行记录
- Then 依据举证链「回滚位置」从废纸篓把该条目恢复到原路径，日志可定位到具体动作与时刻；判定：原路径文件存在且字节数一致、日志该记录含执行动作与 L0 检查时刻（时限见 C3，未拍板前不对外宣称）

**AC-14（权限被拒时的降级）**
- Given Full Disk Access 被拒、废纸篓不可写、或 lsof 因权限受限无法判定别的进程
- When 触发扫描或清理
- Then 产品降级为只读报告，列出受阻来源与所缺权限、不删除任何条目、不把「无法判定」当作「无活引用」、给出可操作的授权指引；判定：磁盘文件数与字节数前后一致、受阻来源列表非空、所有「无法判定」条目的删除动作数为 0

**AC-15（单次上限与条目数上限）**
- Given 候选总量超过 V2 注入的单次上限（待确认）
- When 执行清理
- Then 实际删除量不超过「首次 5 GB 与来源 10% 取小」、稳定后不超过来源 20%、条目数不超过条目数上限，超出部分顺延并留痕；判定：三项约束同时成立、任一触顶即停止、日志记录「上限触顶」一次、顺延条目数等于候选总数减实际删除条目数

**AC-16（规则版本 / 灰度 / 回滚 / 更新后重计观察期）**
- Given 规则带版本号且可灰度、可回滚（V7 待确认）
- When 规则发生更新
- Then 旧规则可回滚、观察期计时器归零、自动删除回到不可点亮状态直到重新通过 C2 合格线；判定：版本号字段可查且新旧不同、回滚后旧判定结果复现、观察期天数计数为 0、开关状态为 disabled

**AC-17（L0 的 TOCTOU 窗口）**
- Given L0 检查已完成，执行前某进程启动并持有了原候选（V6 待确认）
- When 到达删除动作
- Then 删除前 L0 二次检查发现活引用并放弃该条目；判定：该条目仍在原位且字节数一致、日志原因字符串为「二次检查阻断」、L0 检查时刻字段有两个互不相同的取值

**AC-18（举证链字段完整）**
- Given 任一候选被评估
- When 打开其举证详情
- Then V4 的 8 个字段全部有值或显式标注「不适用 + 原因」，无空白、无「以后再补」；判定：8 字段完整率 100%、空白字段数为 0、标注「不适用」的字段均附原因字符串

**AC-19（定时任务的上游能力边界）**
- Given 配置定时任务
- When 选择上游能力
- Then 可执行集合仅含 `uv cache prune`、`brew cleanup --prune`、`npm cache clean --force`、`pipx` 临时 venv 过期、`trash-put`、`z-clean audit` 只读审计，且不含 `uv cache clean`；判定：任务配置与执行日志中 `uv cache clean` 出现次数为 0、集合外命令数为 0

**AC-20（扫描成本预算）**
- Given 目录规模达 328 万文件量级（V8 待确认）
- When 定时扫描触发
- Then 默认走增量、可随时取消、断点可续，满足 N1/N2/N3 的时长与 CPU/电量预算，电池供电且电量低于 20% 时暂停；判定：取消后 5 秒内无新增扫描 I/O、重启后可续扫、N1/N2/N3 三项指标超标项数为 0、低电量时段任务执行次数为 0
