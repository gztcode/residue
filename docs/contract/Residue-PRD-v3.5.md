## 1. 问题陈述〔本节未修订，v3.0 逐字保留〕

跑 coding agent / MCP server 的个人开发者（A1）机器上，一次性工具由 uvx / npx 拉起后把可再生的运行时缓存（~/.cache/uv 50 GiB / 328 万文件、~/.npm/_npx 14 GB 量级）永久写进全局目录且无人回收；而 npm / uv / pip / brew 只维护安装清单、不记录最后使用时间，APFS / relatime / noatime 下 atime 又普遍失真，所以「多久没用就自动删」这类工具拿不到可信的「在用」证据，也没有任何产品敢对误删负责——**病灶不是缺清理工具，是缺一条可举证的「可删」判定链**。

| 要素 | 内容 |
|---|---|
| 谁 | A1 个人开发者 / AI 重度用户 |
| 场景 | 临时用一次的工具被安装、缓存写入全局目录，之后几乎不再用 |
| 痛点 | 磁盘被静默占满，用户既看不见占用来源，也不敢手工删 |
| 现状 | 手工 `uv cache clean` / `npm cache clean --force` / `brew cleanup`，或干脆不清理 |
| 为什么不行 | 手工命令无「在用」判定、会被活着的进程持锁阻塞、无回滚、无举证、无定时 |

## 观察期状态与归零规则（CR-006 · K-6 · 定义性小节，**不新增 AC 编号 / 不新增状态类**）

> 起因：观察期「归零 + disabled」有三个写入口——AC-16 组 A（规则更新）、AC-16 组 B（用户退回规则版本）、AC-08（熔断回退）。原契约无仲裁规则、无版本守卫，会产生双重归零与竞态（架构复核 B4）。

| 规则 | 内容 |
|---|---|
| **单写入口** | 观察期状态与开关状态由**同一状态写入口**维护；三个触发源只**提交归零请求**，不各自直接写状态 |
| **版本号守卫** | 每次归零记录**触发时的规则版本号**；仅当**当前生效版本 = 触发时版本**时，该归零请求才生效。旧版本窗口内产生的恢复事件**不得打回**新版本；**规则更新路径的触发时版本记为更新后的 N**（若按字面记为 N-1、而生效版本已切到 N，该请求会被守卫拒掉，AC-16 组 A「观察期天数计数 = 0」即不可满足，CR-007 · 架构 S-1） |
| **归零语义** | **归零 = 观察期计时器清零 + 样本计数清零 + L2 误判分子清零 + 失联计数清零**，四者必须同时发生（只清计时器不清样本 → 「窗口已重置、分子分母仍是旧值」；只清分母不清 L2 分子 → **分子 > 分母**，直接违反 AC-09 「分子 ≤ 分母」）。**L0 误判计数不随归零清零**：它只在**规则版本切换**（AC-16 组 A）时随版本重置，同版本内的熔断回退与 U1 退回**保留 L0 计数**——即 S2「错 1 次永久不允许点亮」的「永久」= **该规则版本内永久**（CR-007 · R-5 / 待裁 1） |
| **幂等** | 同一版本下重复提交归零请求，结果与提交一次相同 |
| **可观测** | 归零后：开关 = disabled、天数计数 = 0、样本计数 = 0；三个触发源各自的**原因文案不同**，但状态字段与判定项相同 |
| **判定域** | **参与自动删除的来源 = 本机扫描命中、且该来源候选总量 ≥ 1 的上游不自清类来源**；当前版本**封闭枚举为 `uv` cache 与 `npm/_npx` 两类**，新增来源须另出变更单、不得以「等」留开放尾。总量为 0 的来源**不进判定域**、不计入 AC-08 组 A / 组 B、第 ⑤ 页不占行。**判定域为空时，开关区呈现 §8「空」类既有义项「无清理候选」**，不新增未达项、不改「五类」（CR-007 · R-1） |
| **读数快照时点** | 观察期开始时对判定域内各来源做**一次候选快照**：**总量 = 该快照内候选条目数；样本 = 该快照内未被「失联」排除、且被观察到观察期结束的条目数**。观察期内新增候选**进次轮**、不计入本轮分子 / 分母 / 门槛。第 ⑤ 页的「样本 / 门槛」与 AC-08 组 B 一律用**同一快照、同一时点**（观察期结束且 AC-09 报告已生成后）计算（CR-007 · R-2） |
| **熔断状态的进入与退出** | 熔断回退是**状态**不是事件。**进入 = 7 日内 U2 恢复触发率 > 1%**；**退出 = 该次归零请求生效即结束**，转为既有「未点亮 + 观察期」，此后只保留原因文案与 P3 留痕、**不再作为未达项列出**。AC-08 组 A 第 5 项**仅在状态存续期内**列出（CR-007 · R-3） |
| **计数第一键** | **分组计数（样本 / L2 分子与分母 / L0 误判 / 失联）一律以「（来源, 规则版本）」为第一键**，跨版本、跨来源**不混算**；**观察期计时器为全局单实例、不按来源分裂**（开关只有一个，不存在「各来源各自计时」）——这一条同时封住「用来源粒度把计时器拆成多份」的读法（CR-007 · R-5） |
