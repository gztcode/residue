### 1.1 「信号色最多出现一次」的执行口径

v1.1 §二 的原文是「**一个界面上信号色最多出现一次**（主行动或焦点，二选一）」。

v2 **不废除这条规则，只明确它的边界**：

- **信号色**（`#6C79F0`）仍然只用于**主行动 / 焦点**；
- **来源识别色**与**成功 / 警示色**是**新的独立色族**，不计入信号色预算；
- **侧栏选中态占用信号色预算**（它是「焦点」）：主窗口内选中态常驻，
  因此内容区**不再使用信号色**——进度环改用主文字色（白 85%），
  行内标签 / 来源圆点 / 占比条一律用来源色或中性色；
- 若某个页面出现主行动按钮，则它用危险色（本产品的主动作都是不可逆的），
  不产生第二个信号色。

静态断言：`verify_a9.sh` 第五节新增「来源色不得出现在状态语义位置」的检查
（来源色只能经 `Tokens.Color.source(for:)` 取用）。

### 1.2 成功 / 警示色的使用边界

| 色 | 允许 | 禁止 |
|---|---|---|
| 成功 `#46B98A` | 门槛检查项「通过」、观察期已完成 | 任何按钮、任何导航选中态 |
| 警示 `#E8A84C` | 「待结算」「未开始」「需授权」 | 「失败」「错误」（那是危险色） |
| 危险 `#E5534B` | 不可逆动作、错误、无权限、超限 | 普通提示、位置告警 |

> **「未知」仍然不是「失败」**：`passed = nil` 的检查项用三级文字 + 时钟图标，
> 不用危险色。这条与「`nil ≠ 0`」同源。

## 二、数据结构变更（Core，先于视图）

### 2.1 新增 `RatioSlot`

「界面禁止算术」意味着**视图不能自己拿两个数做除法**。原 `SemanticSlot.ratio`
只能显示「27 / 30」，不能驱动进度条。新增只读载体：

```swift
public struct RatioSlot: Sendable, Equatable {
    public let numerator: Int
    public let denominator: Int
    public init?(numerator: Int, denominator: Int)   // 分母 ≤ 0 → nil
    public var fraction: Double                       // Core 侧算好，视图只转 CGFloat
    public var percentTenths: Int                     // 452 = 45.2%
}
```

- **分母 ≤ 0 → `nil`**，界面画空轨道 + 「—」，**不画 0%**；
- 分子可以大于分母（如 `K > H`），`fraction` 上限裁到 1；
- 视图只能调用 `fraction` / `percentTenths`，不得出现 `/` 或 `* 100`。

### 2.2 新增页面模型字段（全部由 `PageModelBuilder` 填充）

| 字段 | 用途 |
|---|---|
| `totalScannedSlot` | ① 页主数字（三来源合计） |
| `sourceShares: [SourceShareRow]` | ① 页堆叠条 + 来源明细表 |
| `reclaimableShare: RatioSlot?` | ① 页「可释放 / 总量」条 |
| `observationRatio: RatioSlot` | 侧栏 / ① 页 / ⑤ 页共用 |
| `observationDaySlot` | 「x / 14 天」（**唯一格式化处**） |
| `gateChecks: [GateCheckRow]` | ⑤ 页门槛清单；`passed: Bool?`（`nil` = 无法判定） |
| `sampleProgress: [SampleProgressRow]` | ⑤ 页逐来源样本进度条 |
| `confirmRows: [ConfirmItemRow]` | ⑥ 页批次预览清单（**只读**） |
| `confirmListTruncated` | ⑥ 页是否因上限被截断 |

`CandidateRow` 增加 `sourceKey` 与 `share`（占总量比例），供 ② 页来源圆点与占比条。

### 2.3 门槛清单不得成为第二套判定

`GateEvaluator.checklist(...)` 是**新增的展示投影**，`isQualified(...)`
改为「清单全部 `passed == true`」。两者**同一实现**，不允许各写一遍。

## 三、⑥ 页：列表化，但**不做勾选**

预览稿里 ⑥ 页有复选框。落地时**不实现勾选**，原因：

- CR-023 已裁定 ⑥ 是「**自动执行批次的预览**」，不是手动删除入口；
- 勾选意味着「用户可以改变批次成员」，这会引入新的执行语义
  （部分执行、上限重算、举证链 `restorePath` 对应关系），必须另开变更单；
- 做一个**看得见但点不动**的复选框，比不做更糟（「空实现按钮」同类问题）。

落地形态：批次内条目**逐行列出**（来源点 + 路径 + 大小），全部标「将执行」，
上限 50 行，超出时显示「仅显示前 50 条」与总数。用户看到的是**将要发生什么**，
不是一个假的可选项。

## 四、菜单栏：`.menu` → `.window`

ADR-02 只约束「单进程 + 菜单栏常驻 + 关窗驻留」，**未约束菜单栏弹出形态**。
原 `.menu` 只能放 3 条命令，无法承载「一眼看到占用与观察期」。

改为 `.window` + 360 × 404 浮层，内容：

1. 已扫描缓存（主数字）+ 可释放条目数 + 字节占比
2. 观察期进度环 + 「x / 14 天」
3. 三来源占比条
4. 达标 / 未达标的只读说明（未达标时明确「不会执行任何删除」）
5. 动作：打开主界面 / 立即扫描 / 退出

**不新增常驻采样**：浮层只读 `AppModel.pageModel`，与主窗口同源。

契约文案（`UICopy`）**一字不改**；`verify_a9.sh` 第四节继续逐字核对。

### 5.1 渲染工具的两处必要让步

- **③ 页画布加高到 1180 pt**：产品内是 `ScrollView`，离屏渲染不渲染滚动内容；
  若仍按 640 pt 出图，页头会被挤出画布。仅 ③ 例外，其余页仍为真实 640 pt。
- **⑦ 页改为两栏**（执行记录 | 举证链字段），上游命令单独一卡：
  原直排高度超出首屏，留存口径底栏会压住最后一行命令。
- **渲染外壳顶部对齐**：错误态比常态多一条横幅，内容会超出 640 pt；
  默认居中对齐会把页头裁到画布上沿之外。改为 `.topLeading` + 侧栏固定
  `height`，只裁掉屏幕下方的内容，与真实窗口「首屏」一致。
- **加载态在渲染路径画静态圆弧**：`ImageRenderer` 不渲染 `ProgressView`，
  实测算出来是黄色「禁止」占位符（13 号图）。产品路径仍用系统转圈。
- **空态上限**：`EmptyStateView` 自带 `maxHeight: .infinity`，放进卡片会
  无限撑高（15 号图记录卡被拉到 340 pt）；⑦ 页两处空态显式给上限。
