## 二、`a` 判据专项审查（阳性差集）

### 2.1 判据本身对不对：「本轮新变成被持有的候选」是否恰好等于 L0 误判？

**判定：不成立。** 阳性差集与 L0 误判原义（「首检无活引用 → 复检有引用」）在三个位置分岔，且分岔方向都指向**误计**。

| 检查项 | 判定 | 依据 |
|---|---|---|
| 判据语义是否 = L0 误判 | **不成立** | 「本轮新变成被持有」= **相邻两次扫描间由阴转阳**；L0 误判 = **首次判定为阴 → 其后某次为阳**。两者在三个边界不同：① 首轮无 `P_prev`；② 间歇性转阳（第二次及以后的转阳）；③ 「上一轮」的指代（M1「轮次」vs「上一次扫描」）。 |
| 「首检」语义是否可由阳性差集表达 | **不可表达** | L133 的载体只有「上一轮阳性集合」，**不含任何「该候选曾被判阴性」的记录** → 「首检」这一必要历史信息在载体里根本不存在。要让 L134 成立，载体必须能回答「此候选是否**曾经**阴性过」→ 需逐候选首检标记（上轮 #1 方案 α 的 1 bit 位图，300 万 bit ≈ 375 KB，与候选数有关但与**行数**无关、字节量级可忽略）。阳性差集在数学上给不出这个信息。 |
| 是否存在「上一轮被持有 → 本轮被持有 → 但其实是误判」的情形 | **存在** | X 在 D1 阴性、D2 起被持有且**持续**被持有 → 差集只在 D2 命中一次，D3 起不再命中 → `a` = 1。这本身正确。**但**若 D3 时进程退出（X 转阴）、D4 又被另一进程持有 → D4 差集再次命中 → `a` = 2，而按 L134「同一条候选只计一次」应为 1 → **同一台机器两个 `a`**（见 13-A2）。 |
| 是否存在「上一轮没被持有 → 本轮被持有 → 但其实不是误判」的情形 | **存在（且高频）** | ① **自始被持有者**：X 从产品第一次扫描起就被持有（D1 阳性，`P_prev` = ∅）→ 差集命中 → **计 `a` = 1**，但 X 从未被判阴性 → 按 L134 不是误判 → 按 L133 是 → **两读**（见 13-A1）；② **跨版本继承者**：应用版本变更后 `P_prev` 是否清零未写 → 见 13-A7。 |
| 「聚合吸收」是否已消解 | **已消解** | 逐候选差集比对，一个持续被持有的候选不吸收其它候选的误判 → v4.5 的病灶①（`a` 恒为 0）确已消除。本轮的失败**不在**聚合吸收，而在判据语义本身。 |
| 「同一条候选只计一次」是否成立 | **不成立** | 差集只能保证「**连续**持有不重复」，不能保证「同一条候选终身只计一次」；滚动替换使已计过的候选离开 `P_prev` → 间歇性持有**重复计数**（见 13-A2）。L134 明写该性质「由『该候选已在上一轮阳性集合 `P_prev` 中 → 本轮差集不再命中』**自然实现**」——这句**自然实现是错的**。 |
| 「唯一判据」是否全文唯一 | **不唯一（三处复述、两种口径）** | ① M4 判据行 L133（阳性差集）；② M4「唯一判据」行 L134 + 符号表 L77（「首检无活引用 → 复检有活引用」）；③ M4「计数对象」行 L138（「首检无引用 → 复检有引用」事件）。②③ 与 ① 在首轮与间歇性场景下读数不同。 |
| 载体规模是否与候选总数无关 | **表述不成立（作为契约级不变量）** | `P_prev` 规模 = 该来源**当前被持有的候选数**。M4 L137 自称「通常个位数」，但**全文无任何机制把被持有候选数限制在候选数的小比例内**（P-L0 的持有面 = fd / 文件锁 / cwd 三者之一；§1 量级 = uv cache 328 万文件 / 50 GiB）。契约级可写的只有「远小于候选总数」，**写不出「无关」**。**但此项不构成阻塞**（即便 `P_prev` 达到候选数的相当比例，它仍远小于 v4.6 的阴性全集方案、仍不落 `.jsonl`、仍不被回收触及 → 机制仍闭合）→ 见建议 S2。 |
| `P_prev` 滚动替换是否正确 | **不正确** | 替换使「曾被计过的候选」信息丢失 → 重复计数。正确形态 = 差集 ∩ 一个**单调增长**的「已计过误判候选集合」`C_done`（只增不减，规模 = 累计误判候选数，仍与候选总数无关）→ 见 13-A2 修法。 |
| `a` 的写入时刻是否唯一 | **不唯一** | M4 写入时刻行 L137 写「**复检时刻**（即复检发现活引用的那一刻）」；L133 写「**每轮扫描结束后**…计 `a` += …」；L137 又写 `P_prev`「**随每轮判定滚动替换**」→ 三个时点（逐候选复检时刻 / 每轮扫描结束 / 每轮判定完成）→ 读数时机与滚动时机不同步（见 13-A3）。 |

## 六、本轮结论

- **结论：不通过**（阻塞项 7 条 / 建议项 7 条）
- **上轮 6 条修法：成立 3 条（A2 / A4 / A6），不成立 3 条（#1 判据 / A3 起算点三处同改 / A5 举证链粒度与 AC-18 分母）**
- **`a` 的判据（阳性差集）：不成立。** 判据方向仍错——阳性差集**在数学上无法表达「首检」语义**（载体不含「该候选曾被判阴性」的历史），导致：首轮 `P_prev` 无定义 → 三处复述两口径（13-A1）；滚动替换 → 间歇性持有重复计数，「同一条候选只计一次」落空（13-A2）；「上一轮」与 M1「轮次」二义（13-A3）；版本变更未清 `P_prev` → 换版必脏（13-A7）。**且这一组缺陷的后果不是「`a` 恒为 0」（v4.5 形态），而是「`a` 恒 ≥ 1」——L0 零容忍门槛以误报恒真的形态回归，且因 `a` 只在应用版本变更清零而用户无自救路径（死局）。**
- 建议下轮采用上轮已给的**方案 α**（每候选 1 bit「首检标记」+ 单调增长的「已计过」集合 `C_done`）：它一次性同时解掉 13-A1 / 13-A2 / 13-A7，且字节量级（≈375 KB–750 KB）与候选**行数**无关、仍不落 `.jsonl`、仍不被容量回收触及、不新增 AC 编号 / 页面 / 状态类 / 用户动作。
- 其余四条阻塞（13-A3 术语与时点、13-A4 文件头① 第三处同改、13-A5 举证链粒度与留存终止条件、13-A6 AC-18 分母两读）**均为定点措辞修**，不涉及机制级重做。
