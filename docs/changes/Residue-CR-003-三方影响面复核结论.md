## 5. 架构侧两项技术事实（登记备查，不构成本单阻塞）

1. **Hardened Runtime ≠ App Sandbox**：HR 限制代码注入 / JIT / 调试 / library validation，不做文件系统隔离；只读扫描的 `stat` / `readdir`、`rename_to_trash` 到 `~/.Trash`、P-L0 的 fd / 文件锁 / cwd 枚举（libproc）均不需 entitlement、HR 不拦。FDA 未授予时的降级是 v3.0 已登记的 OS 固有约束，与渠道 / 签名无关。
2. **`NSWorkspace.open` 走本机 XPC / Mach IPC**（回环，P1 已过滤），对外 HTTPS 由浏览器进程发起，既非产品主进程亦非派生 CLI 子进程，本就在 P1 观测对象之外；发布侧 `notarytool` 属 CI、Gatekeeper 校验属系统进程（F11）。

**R2 交接项（H6 已框定、不阻塞本单）**：须走系统转交，**不得用 `WKWebView` / `URLSession` 内嵌加载**，否则外发回到产品进程树；若 R2 取「派生 CLI 子进程」调 uv / npm / brew，HR 的 library validation 可能需 `disable-library-validation` 或改不注入启动方式；helper 逐二进制签名拓扑、进程模型形态、`SMAppService` 用法同理。以上均为 R2 选型产物，不在契约层预设。
