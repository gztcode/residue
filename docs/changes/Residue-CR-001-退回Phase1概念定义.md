## 用户裁决（已拍板）

- **概念 A → A-α**：废止「在线 / 离线 / 在线安全 / 在线自证」四个需求术语，采用 T1 本地引用可达性 / T2 并发活引用 / T3 网络连通性 / T4 零外发四个互斥术语；移除 §8「离线」状态类（属删除，非新增状态类）；不得放宽 A3 / N7 / N8 / §7 的零外发约束。
- **概念 B → B-α**：「回滚」按 U1 规则版本退回 / U2 文件恢复 / U3 批次事务回退 / U4 数据迁移回退（Backlog）四个对象分离并分别定名；**废止「灰度」**（单机无放量对象），AC-16 的 `{未灰度/灰度中/全量}` 三态一并废止；规则更新的安全保证由既有 AC-08 组 B / V1 观察期 / C2 合格线 / S2 闸门 / R1-17 承载，不新增机制。
- **术语定名、条文措辞、承载页归属由团队内部定，不回问用户**（决策权下沉）。
- 两案均**不冲击八条锁定决策**，无需另开范围变更单；PRD v3.0 由柯求真按此产出，随后由原三名评审人重提 **R1 新一轮**（提案人回避）。B1 / B3 在 v3.0 通过复核前仍登记「未关闭」。

> 与「砍范围」选项②的区别（留痕）：用户选的是「换方案，退回需求层」，**不是**把 AC-16 整条转 Backlog。若后续有人以「双 α 已废止灰度」为由把 AC-16 整条移出本期，属越权，须另开范围决策变更单。

## 回退范围（只有两项）

1. **「在线安全能力 / 联网前提」**：消解 P1、N6、AC-01、AC-12、§8「离线」、以及 R1-01 / 设计 B3 的跨条文错配。
2. **「规则灰度 / 回滚」**：消解 AC-16、V7、N9、§6 承载页、以及 R1-13 / 设计 B1、质量阻塞 14 的分歧。

**疑似根因（交付总监观察，交产品经理独立验证，不代下结论）**：
- 「在线安全」疑似把两个不同维度混成一个词——①「服务运行中仍可执行」（进程在线，`uv cache prune` 可在 MCP server 活着时跑）②「需要网络连通」（网络在线，`brew cleanup` 默认触发 update）。若成立，§8「离线」这个空状态就是词义混淆的产物。
- 「灰度」疑似是从服务端语境误植到**单机、单用户、无账号、无控制面**的本机工具——单机没有"分批放量"的对象；「回滚」疑似混了三个不同对象：规则版本退回（AC-16）、文件从废纸篓恢复（AC-13）、应用数据迁移回退（C-06 已转 Backlog）。

## 明确不回退（八条锁定决策全部不动）
