## 一、数值裁定：AC-15 的条目数上限 = **200 / 来源 / 单次**

### 为什么需要我定

PRD 的 V2 原文：

> `V2` | 单次上限：首次 ≤ 5 GB 且 ≤ 该来源 10%（取小）；稳定后 ≤ 来源 20%；另设条目数上限（**数值待定**） | **建议值 · 待确认**

并且 AC-11 的判定特意声明：

> V2 条目数上限数值为「建议值 · 待确认」，**不作为默认值唯一性的判定基准**（R1-20）

也就是说**契约有意没把它钉死**，留给实现定。而 AC-15 的判定要求「条目数上限」必须是**可观测结果之一**——不定值就没法判。

### 裁定值：200 条 / 来源 / 单次

**依据是一致性，不是拍脑袋**：

| 事实 | 推论 |
|---|---|
| ② 页候选清单的分页就是 **200 行/页**（ADR-01） | 「用户看到的一页」= 「一次能删的上限」 |
| 两者是同一个数 | 用户对「这次会删多少」有直观预期 |

**反面**：若上限是 3000，用户只看了一页（200 条）就点确认，结果删了 3000 条——**这不是预期不符，是知情同意失效**。

### 若产品后续给出定值

改 `AppModel.itemCapPerSource` 一个常量即可。已在本单登记，不散落在多处。

## 二、三个「空 action」按钮已接真实动作

### 它们原先都是空实现

| 页 | 按钮 | 原先 | 现在 |
|---|---|---|---|
| ④ | 一键清除采集物与日志 | action 里只有一行注释「骨架阶段：动作由后续接」 | `app.clearLogs()`（AC-12） |
| ⑥ | 立即执行本次清理 | **只关抽屉**（`showConfirmDrawer = false`） | `await app.executeBatch()`（AC-04） |
| ⑦ | 恢复 | action 里只有注释 | `app.restore(record)`（AC-13） |

### 为什么这一类缺陷比「没有按钮」更糟

**空 action 的按钮会让人以为做成了。** 用户点「立即执行」，抽屉关了，界面回到原样，什么都没删，**也不报错**——
他会认为「清理已完成」。这比一个灰掉的按钮危险得多。

而这类缺陷**任何读代码的方式都容易漏**：`Button("X") { }` 语法正确、能编译、能渲染、UI 测试也能点到它。

### ⑥ 的语义要说清（否则又会被当成「手动删除入口」）

CR-023 已裁定：本产品**没有「用户手动删文件」这条路径**（AC-04 只写「到达定时执行点」）。
⑥ 那个按钮做的是「**把本次定时批次提前执行**」，因此：

- **受 AC-04 全部门槛约束**（`executeBatch()` 第一件事就是检查 `canLightUp`）
- 所以**不存在「手动清理绕过观察期」**（原 S-8 因此消解）
- 门槛未过时按钮 disabled，并在下方显示原因（不给「点了没反应」）

## 三、`EvidenceRow` 补 `record`（恢复能力的数据通路）

**问题**：`EvidenceRow` 原先只有 `path` + `label`，而 `TrashExecutor.restore` 需要 `restorePath`
——它只存在于 `ExecutionRecord` 里。**没有这个字段，AC-13 的恢复能力就不存在**，只能做成空按钮。

**处置**：`EvidenceRow` 增加 `record: ExecutionRecord?`，由 `PageModelBuilder` 从 `executions` 带入。

**并且加了一条条件**：恢复按钮的出现条件是
```swift
if case .recoverable = row.label, row.record != nil
```
只判标签的话，遇到「日志里有、但还原不出 `restorePath`」的行，按钮会出现而点了没反应 —— 又回到空实现的形态。

## 五、`executeBatch` 的实现要点（AC-15 两档上限）

```swift
// 「首次」= 本机首次产生实际删除动作（AC-15 的阶段分界）
let isFirstRun = executions.isEmpty
cap = isFirstRun
    ? min(5_000_000_000, Int64(Double(total) * 0.10))   // 首次：min(5GB, T×10%)
    : Int64(Double(total) * 0.20)                        // 稳定后：T×20%
```

| 要点 | 说明 |
|---|---|
| `pipx` 恒不参与 | `guard source.isInDecisionDomain` —— AC-04 ② |
| `T` 未取快照时 | 退回候选字节合计（如实降级，不假装有快照） |
| 顺延条目数 | `outcome.skippedByCap` 汇总 → ⑥ 页「顺延条目」（AC-15 三项约束之一） |
| 每条记录落 `execution.jsonl` | AC-18 举证链的数据源 |
