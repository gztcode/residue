## 二、逐条改动（7 条）

### 偏差 1 · AC-14 Given 第三类「`lsof` 因权限受限」失去触发物

**PRD 现状（AC-14 Given，原文）**：
> Given Full Disk Access 被拒、废纸篓不可写、或 **lsof 因权限受限无法判定别的进程**（三类受阻来源各自可独立构造）

**为什么必须改**：方案 ADR-03 已定「用 `libproc` 直接枚举同 uid 进程 fd，**不 spawn `lsof`**」——理由是 `lsof` **静默丢权**，导致「看不到」与「没有」不可区分（违反 N5）。`lsof` 不用了，这条 Given 的**触发物不存在了**。同时「FDA 是否授予」在 macOS 上**没有公开 API 可判**。

**改法**：

| 项 | 改前 | 改后 |
|---|---|---|
| Given 第三类 | lsof 因权限受限无法判定别的进程 | **同 uid 进程的 fd 枚举失败** |
| FDA 定位 | 前置授权（隐含） | **失败后的补救指引**（只有①来源不可读或②枚举失败时才提示「可能需要在系统设置 → 隐私与安全性 → 完全磁盘访问权限中允许 Residue」） |

**同时必须删的一句**（否则改完仍矛盾）：AC-14 判定末尾的「**全篇 P1 / N6 / §8 不再向本 AC 挂靠任何网络 / 探测失败场景**」——该澄清是为 `lsof` 那一类准备的，改后**第三类已不是「探测失败」**，澄清句要跟着改。

**影响面**：
- ✅ 保留：AC-14 的 Then（降级只读、逐条列受阻来源、不把「无法判定」当「无活引用」）与判定（前后一致、不删除、状态词可区分）——**这些是安全底线，一条不动**
- ⚠️ 改动：AC-14 Given（第三类）+ 判定末尾澄清句
- 🔗 关联：AC-08 组 A 的未判定态、§8「无权限」类、P4 状态词表（「无法判定」）
- 📉 用例影响：原「三类受阻各自可构造」→ 变为**两类可构造 + 一类（`lsof` 受限）失去触发物**。安全合规检查表 S-02 的结论已同步改为「需验证（仅『来源不可读』可构造）」。**R3 用例按新 Given 写。**

### 偏差 2 · AC-15 / M6 未定义「目录的字节」→ 上限判定恒真

**PRD 现状**：AC-15 说「实际删除量不超过『首次 5 GB 与来源 10% 取小』…」，但**全文没有一处定义「量」怎么算**。用 `st_size` 的话，一个目录本身只有 ~96 B（APFS 目录 inode 固定大小），**不含其内容**。

**为什么必须改**：用 `st_size` 判容量上限 → **判定恒真**（永远「没超」）→ AC-15 的容量上限**形同虚设**，同时 M6 的「可回收字节」也失真。

**改法**：AC-15 与 M6 各补一句定义：

> **目录的字节 = 该目录下全部普通文件（递归）的 `st_size` 之和**；目录自身的 `st_size` 不计入。

**影响面**：
- ✅ 保留：AC-15 的三项约束（容量上限 / 条目数上限 / 顺延留痕）与阶段分界（首次 / 稳定后）**全部不动**
- ⚠️ 改动：AC-15 与 M6 各增一句计量定义
- 🔗 关联：M6「可回收字节」算式（该算式量的是**日志目录**字节，与本条不冲突，但两处都写「字节」→ 需各自限定，避免实施方混用）
- 📉 用例影响：**AC-15 的容量上限用例从「不可构造」变为「可构造」**（原判据恒真，是 R2 评审时质量组抓出来的真问题）

### 偏差 4 · M4 未限定「持有」的进程范围 → 声称了做不到的事

**PRD 现状（P-L0「持有」判据表）**：
> 某进程对候选路径持有 fd / 文件锁 / cwd 三者之一即为「持有」。… **FDA 未授予时无法可靠枚举别的进程 fd，产品按 AC-14 降级只读**，既不报「L0 活引用阻断」也不报「无活引用」。

**为什么必须改**：跨 uid 进程（含 root）持有的文件，`libproc` 枚举必然 `EPERM`——**产品看不到，且 FDA 也不解锁**（这是 R2 阶段实测确认的）。若 M4 不限定判定域，实施方按「全系统进程」理解 → 界面 / 报告写「全系统无活引用」「无任何进程占用」→ **声称了做不到的事**，直接违反 N5。

**改法**：P-L0 判据表补一句限定：

> **判定域 = 同 uid 进程**。跨 uid 进程（含 root）持有的文件**本产品不可见**（`EPERM`，FDA 不解锁）→ 因此凡声称「无活引用」的场合，**只能写「本用户进程无引用」**，不得写「全系统无活引用」「无任何进程占用」。
> **判定域写死的后果**：`a` 的判据不受影响（跨 uid 不可见只会导致「漏保护」，不会「误计」）；但**「其他用户可写」的目录**（`stat` 的 mode 含 group/other write 且非 sticky）其来源**不进入自动删除候选集**（只进报告）——这类目录在 `~/.cache` 下正常不存在，但**不能靠「正常不存在」来保证安全**。

**影响面**：
- ✅ 保留：P-L0 的「fd / 文件锁 / cwd 三者之一即为持有」、L0 检查窗口（首检 → 删前二检）——**不动**
- ⚠️ 改动：P-L0 表增判定域限定 + 文案禁写清单 + 「其他用户可写目录」保守化补丁
- 🔗 关联：M4 判据（`P_now` 的定义域）、ADR-03、AC-05 / AC-17 / AC-14 / N5
- 📉 用例影响：L0 判定用例的**断言粒度**从「无活引用」改为「本用户进程无引用」；新增「其他用户可写目录不进入候选集」一条可观测结果

### 偏差 5 · AC-10 进程级表述 vs 方案任务级表述

**PRD 现状（AC-10）**：
> Then 四档信号采集全部停止、**常驻监听进程退出**、界面四档状态逐一显示「已停止」且可验
> 判定：… 按已登记标识**无常驻事件监听进程存在**；…

**为什么必须改**：ADR-02 已定「单 `.app` + 菜单栏常驻」——**产品本身就是单进程常驻**。若按 AC-10 字面判「无常驻进程存在」，**这条永远不可满足**（或被迫谎报）。AC-10 的真实诉求是「**没有常驻的采样任务在跑**」，不是「进程不在」。

**改法**：AC-10 两处**规范性断言**改为**任务级**表述：

| 位置 | 改前 | 改后 |
|---|---|---|
| Then | 常驻监听进程退出 | **无常驻采样任务在运行** |
| 判定 | 按已登记标识无常驻事件监听进程存在 | 按已登记标识**无常驻采样任务在运行**（任务级判定，非进程级） |

**同时**：AC-10 的「四档全停」对象定义已写明「= 四档信号采集 + 第 4 档常驻**采样进程**」→ 该处「进程」也一并改「任务」，否则同一句里两种层级并存。

**⚠️ 不得误改的一处**：AC-10 的 Given「**进程模型标识（单进程 / LaunchAgent / helper / launchd 按需 四类）已登记可查**」——这是**部署形态的枚举清单**（记录产品选了哪一种形态），**不是「无常驻」的断言**，**一个字不动**。误把它改成任务级会毁掉「进程模型可查」这个判据。

**影响面**：
- ✅ 保留：AC-10 的核心判定——**「关闭后一个完整定时任务周期内（≥ 下一次每日任务触发）新增采集日志条数为 0」**（这是 R1-03 把恒真的「60 秒内 0」改成的可证伪窗口）**一条不动**
- ⚠️ 改动：Then / 判定 / 「四档全停」对象定义，三处「进程」→「任务」
- 🔗 关联：ADR-02、N3（定时任务）、AC-11 四档、P4「已停止」
- 📉 用例影响：AC-10 的可观测结果从「进程不存在」（不可构造）改为「采样任务不运行 + 新增日志 = 0」（可构造）
