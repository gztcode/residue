# Residue · CR-033 · 第 ⑤ 页非判定域行 ④ / ⑥ 取值逐字化

- **变更单号**：CR-033
- **状态**：已实施（2026-11-14），待评审
- **来源**：CR-032 §十五 L-2；DAC v2.1 §8.1 **M-9**
- **影响契约**：PRD v5.6 AC-09 判定 · B1 v1.2 TC-050 · 视觉基线 v1.1 §四（矩阵单元格取值形态）
- **改动性质**：**取值逐字对齐**，不新增页面、不新增列、不改行集合、不改任何判定算法

---

## 一、一句话结论

`pipx run` / `pip cache` 两行（非判定域行）在 ⑤ 页矩阵上的 **④ 门槛** 与 **⑥ L0 误判 · 检查** 两列，
原来填的是「不适用」与 `0 次 / 0 次`；现按 PRD AC-09 判定**逐字**改为
「不适用（不入判定域）」与「不适用 · 未执行 L0 检查」，且 ⑥ 由「两个数值」变为**整格一句**。

`0 次 / 0 次` 不是「没检查」，是「检查了 0 次且误判 0 次」——**把未知说成了干净**。

---

## 二、缺陷（判据 + 实施前现状）

| # | 列 | PRD AC-09 判定逐字要求 | 实施前实现 | 判定 |
|---|---|---|---|---|
| 1 | ④ 门槛 | 「不适用（不入判定域）」 | `.text("不适用")` | **不通过**：读者分不清「不参与判定」与「门槛算出来是 0」 |
| 2 | ⑥ L0 | 「不适用 · 未执行 L0 检查」 | 两个 `.metric`：`a` 次 / `b` 次（该行恒 `0 / 0`） | **不通过**：`0 / 0` 会被读成「检查了 0 次、误判 0 次 = 干净」 |

判据出处：`docs/contract/Residue-PRD-v5.6.md` 第 1067 行（AC-09 判定「每项均须非空」段）逐字规定：

> …④ 填「不适用（不入判定域）」；⑤ 固定「该来源不适用（无观测通道）」；⑥ 填「不适用 · 未执行 L0 检查」；⑦ 恒「仅报告」。

对应用例：`Residue-B1-功能用例集-v1.2.md` TC-050（`pipx run` 行取值）。

**为什么这是缺陷而不是「文档过时」**：`0 / 0` 违背本产品第 3 条核心不变量
（不把未知判为安全 —— 看不见的东西如实显示「无法判定」，不显示 0、不猜）。
该行从未执行 L0 检查，`a` / `b` 根本没有值。

## 三、改动清单

### 3.1 契约文案（`ResidueCore/SemanticSlot.swift` · `UICopy`）

新增两个唯一样式串（**界面不得自行拼接**）：

| 常量 | 简中 | English |
|---|---|---|
| `UICopy.notInDecisionDomain` | 不适用（不入判定域） | N/A (not in decision domain) |
| `UICopy.l0NotChecked` | 不适用 · 未执行 L0 检查 | N/A · L0 check not run |

### 3.2 取值（`ResidueCore/PageModelBuilder.swift` · `reportRow`）

- ④：`!inDomain` → `.text(UICopy.notInDecisionDomain)`（原来 `.text("不适用")`）。
- ⑥：`!inDomain` → 单一槽位 `.text(UICopy.l0NotChecked)`，**不再给第二个槽位**（`extraSlots` 为空）。
  判定域行不变：仍是 `a` / `b` 两个独立 `.metric`，报告未产出时左值「本轮未结算」、右值照常填。
- 判定域行的 ④ / ⑥ 逻辑**一行未动**。

### 3.3 渲染（`ResidueApp/ReportPage.swift`）

- ⑥ 列：单元格只有一个槽位时按**整列宽**渲染（拆成两个 62 pt 子格会把句子截成「不适用 · 未…」）。
- ④ 列：该列的**非数值槽位**取 11 pt。该列宽按数值 `H` 定，13 pt 的整句在列宽内折成两行会超出
  32 pt 固定行高（视觉基线 v2 契约值，不动）；11 pt 两行 28.6 pt 装得下。

### 3.4 列宽重排（`ReportPage.columnWidth` + `ReportMatrix.sampleColumnWidth`）

七列合计必须 ≤ **695 pt**（可用宽度 751 − 单元格左右内边距 56）。视觉基线 §五 的已知缺口 B11 明确
「无列宽 / 截断规则」——列宽不是契约值，本单借此把规则写死一次：

| 列 | ① 来源 | ② 判定域 | ③ 样本 / 总量 | ④ 门槛 | ⑤ 观察期 | ⑥ L0 | ⑦ 结论 | 合计 |
|---|---|---|---|---|---|---|---|---|
| 改前 | 100 | 70 | 150 | 70 | 90 | 128 | 80 | 688 |
| **改后** | 86 | 56 | 130 | **144** | 62 | **141** | 76 | **695** |

④ / ⑥ 各自加宽以装下整句文案，差额从其余五列匀出。

### 3.5 设计样例（`ResidueApp/DesignSampleData.swift`）

⑤ 页样例矩阵补齐 `pip cache` 行（CR-032 后共 5 来源），两行非判定域行的 ④ / ⑥ 改用上表的
`UICopy` 常量 —— **样例也是契约证据，写旧值等于把缺陷画进设计稿**。

## 七、硬边界（实施后仍然有效）

1. **删除仍只有一条路径**：`TrashExecutor` 原子 rename 到废纸篓，全文无 `rm` / `unlink`。
2. **判定与算术仍只在 Core 一处**：本单只在 `PageModelBuilder` 换取值，界面不新增任何算术；
   新增的两串文案都进 `UICopy`。
