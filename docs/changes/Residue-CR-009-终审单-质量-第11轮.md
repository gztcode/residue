## 必查 1 · `a` 的可构造性（三轮以来的核心追问）

### 问 1（第三方在真机上逐步怎么做）

**可构造，且不需要任何注入点**。M4 的判据已自足，逐步做法如下（按 v4.4 现状，不含任何新增机制）：

1. 装产品、**授予 Full Disk Access**（M4 139 行：未授予 FDA 时 `a`/`b` 均**不判定** → 不授予 FDA 就没有 `a` 这个量；用例文本未写此前提，但契约可推导）。
2. 让判定域内某来源**至少有 1 条可再生物料候选**（`uv` cache 或 `npm/_npx` 各一条即可），且该来源 `T ≤ 30`（见 Q12，否则 `H` ≠ `T`）。
3. **扫描 #1**：此刻**无任何进程持有**该候选（P-L0「持有」= fd / 文件锁 / cwd 三者之一；不要 `cd` 进它的目录、不要打开它）→ 首检 = 无活引用 → 记为该候选的「首检」。
4. **在两次扫描之间让一个进程持有它**：例如 `tail -f <候选路径>`（fd）或 `cd <候选所在目录>` 后保持该 shell 不退出（cwd 即算持有）。
5. **扫描 #2**（必须在**另一个日历日**，否则不构成两个判定时点）→ 复检 = 有活引用 → **`a` = 1**。

### 问 2（测试周期 · 第三方要花多少天）

- **`a` = 1 这个事件本身**：2 个扫描日即可造出（步骤 3→4→5）。
- **读到 `a` 的数值**：M4「判定前置」（137 行）写死「`a` 只在报告产出后判定」，而报告产出 = 观察期结束扫描 = **本轮第 14 个计数日结束后的第一次成功扫描**（M1 100 行）→ **最短 15 个日历日**（第 1–14 日各一次成功扫描，第 15 日那次为结束扫描并产出报告）。
- **同一条用例还要满足「样本不足态」**（①′）：影子期内**用户手删 1 条** → 手删须发生在快照之后、结束扫描之前，否则 `T` 或 `K` 口径漂移 → 可在第 2–13 日内任选一日执行，不增加周期。
- **可接受性**：15 个日历日 ≈ 两周半，与 V1「影子观察期 14 天」同量级 → **可接受**；但这是**每条正/反向用例**的固定成本，且**观察期用例与留存用例不能在同一台机器、同一时间线上共存**（唯一加速手段 = 改系统时钟 → 同时污染 N7 的「14 日内执行记录」与「90 天期限」两个日志年龄口径；契约**未写「可注入时钟」**）→ 见 **S4**。

### 问 3（追加举证链行后，`a` 的判定是否真能命中）

**能命中。** 逐项核验：

- **记录粒度**：M4 写入时刻（134 行）「**每候选每轮扫描追加一行举证链行**（不覆盖旧行）→ 复检时追加新行，首检行保留 → 首检证据不会被复检覆盖」→ 同一候选在两次扫描后**存在两条判定记录** → M4 判据「首检无活引用 → 其后某次扫描出现活引用」可被命中 ✓。
- **证据被回收不漏计**：M6 豁免边界（163 行）「M4 判据所依据的「前一次 L0 判定结果」以产品本机对该候选**最近一次判定结果**为准，不以留存计量回收后的举证链行为准」→ 即便举证链行被容量回收删掉，`a` 仍正确累计 ✓。
- **跨轮一致**：`a` 按 (来源, 应用版本) 分组、跨轮次累计（89 行 / M4 136 行）→ 判据的「其后某次扫描」不限定轮次，与分组键一致 ✓。
- **仍有的三个失效点**（不判阻塞，进建议项）：
  ① **M4 措辞自相**：134 行同时写「该次判定写入**该候选本轮的举证链行**」（读作本轮唯一一行）与「**每候选每轮扫描追加一行**」（读作本轮多行）→ 建议写死「同一候选本轮多行、最早一行为首检」（**S8**）。

  ③ **用例 ①′ 的预期不唯一**（手删候选与被持有候选未区分为不同候选）→ **Q11**。

## 必查 2 · `b` 与 `a` 的门槛关系

- **`b` = 1 时 `a` 是否恒 0** —— **是，且是真值**：`a` 的判据要求「首检无活引用 → 其后某次扫描复检有活引用」→ 至少两个判定时点 → `b` = 1 时 `a` 只能是 0；这个 0 是「只判过一次、本来就没有误判可发生」的真值，不是「无脑满足」的假通过。
- **组 B 只要求 `b` ≥ 1 时门槛是否形同虚设** —— **门槛本身空转，但 `b` = 1 态不可达**：
  - M4 前置（130 行）「**每轮扫描时**，产品对判定域内每条可再生物料候选执行一次 L0 判定——**影子期内同样执行**」+ M5 判据（145 行）「影子期内每次扫描对判定域内每条可再生物料候选**至少**执行一次 L0 判定」→ **已满（14 个计数日）⇒ `b` ≥ 14 × 该来源候选数 ≥ 14** → 「`b` = 1」在所有可验收状态下**不可达** → 「`b` ≥ 1」在所有可验收状态下**恒成立、无判别力**。
  - 它防的那一情形（「`a` 在 `b` = 0 时恒真」）已被 M4 前置从源头堵死 → `b` ≥ 1 的真实定位是**完整性要求**，不是阈值型门槛。
- **「`a` 有判别力需要 `b` ≥ 2`」这个区别写进契约了吗** —— **没写**。M5「门槛地位」行（150 行）只写「**`b` ≥ 1 是 AC-08 组 B 的门槛项之一**（否则 `a` = 0 在 `b` = 0` 时恒真、可无脑满足）。**故 `b` 不是「观测面」**」—— 只解释了「为什么不能是 0」，**没有**写「本门槛在已满态恒成立；`a` 有判别力的最小条件 = 至少两个跨扫描的判定时点（`b` ≥ 2），已由 14 个计数日自动满足」。上一轮 S4-③ **未处理** → 进 **S3**（不判阻塞：该区别不影响任一断言的预期唯一性）。
- **另注**：`b` = 0 分支在组 A **结构上恒假**（已满 ⇒ 每轮扫描对每条候选判一次 ⇒ `b` ≥ 14；来源项又是报告产出后判定）→ 组 A 文案「`uv cache · L0 未检查（检查 0 次）」是**死条文**（上一轮 Q4 核验残留）→ 进 **S2**（不判阻塞：死条文不产生错误预期，只是不产生判别力）。

## 复核说明（不改变结论）

1. 本单只判「这条能不能被第三方写成用例、预期是否唯一」。凡属「设计好不好 / 方案选不择得对」一律未评；凡属已裁决项一律按现文接受。
2. **本轮未重开任何已裁决项**：四维度范围、`H = min(30, T)`、14/90 天 / 200 MB、14 日豁免、S4 / AC-16 / L2 / 期内样本进度不交付、不新增 AC 编号 / 机制 / 页面 / 状态类 —— 7 条阻塞的修法合计**只改既有定义 / 条文的一两处**：Q11 / Q15 是**补用例文本与一句区分**，Q12 是**补构造前置**，Q13 是**四处口径引用同步**，Q14 是**补一句终态兜底**，Q16 是**二选一写死计数日封顶**，Q17 是**组 B 改为引用 M1**。**未引入任何新的量、新的机制、新的页面、新的状态类、新的未达项类、新的 AC 编号**。
3. **没有「建议整体重做」可成立的理由**：7 条阻塞全部落在「同一个量在两处被定义」或「一个判据把两个事件绑在一起」这一类，与第 8–10 轮根因同型；Q16 / Q17 是上轮 Q7 拆开「成功扫描 / 结算报告」时**未同步到组 B 与计数日封顶**的两处落点，Q13 是上轮 Q9 统一口径时**未同步到 N7 / N8 / P5 三处引用**的落点，Q11 / Q12 是上轮 Q10 改口径时**未补齐构造前置与候选区分**的落点 —— 全部是定点修，逐条改一段文字即可闭合。
