## 裁决内容

**上游命令只做只读探测与举证，删除动作一律由产品按 N5 执行（原子 rename 到废纸篓）。**

- `uv cache prune` / `brew cleanup --prune` / `npm cache clean --force` / pipx 过期清理等**直接删文件的上游命令，从可执行集合移除**。
- 只读定位与举证命令（`uv cache dir`、`npm cache ls`、`brew --cache` 等）进入集合，用于 L1 判定取证。
- `trash-put`（非 macOS 原生第三方命令）、`z-clean audit`（全文无定义）**不再作为执行动作**，其审计价值由只读方式保留或剔除，须在 v3.0 写明。
- 「pipx 临时 venv 过期」属行为描述而非命令，从命令集合拆出，改为状态/条件登记。

## 已知代价（如实登记，不粉饰）

- 产品须**自研本地引用图可达性判定**来替代 `uv cache prune` 的能力 → 工程量与误判风险上升，属 R2 方案层必须核算的成本。
- 归因须改写：不再是「失去在线剪枝能力」，而是「本地引用图判定须自行实现 + prune 本身是真删除不可用」。依据：概念卡 §0 的 F1 / F2 / F3 / F5 核实结论（三条 prune/clean 命令全部纯本地、不需联网）。
- **上游 prune 是真删除、不进废纸篓这一核心冲突与网络无关**，本次裁决以「不调用」而非「改造上游」的方式消解。

## 一道必须守住的约束（交付总监设置）

产品自研的「本地引用图可达性判定」只能用于 **L1 层生成/缩小候选**，**不得成为删除的正面授权**。

删除的正面授权仍只能是：**L0 无活引用 + 只清可再生物料 + 观察期通过 + 单次上限 + 未被 L2 弱信号或白名单排除**。

理由：我们前面确立的安全边界是「由范围定义、不由判定引擎精度定义」，且 L2 只有否决权无许可权。若把自研可达性判定提升为「证明可删」的许可依据，等于把 atime 那套换个名字请回来，直接违背决策 ⑦⑧。此条写入 v3.0 的 L1 定义，R1 新一轮须由架构与质量各复核一次。
