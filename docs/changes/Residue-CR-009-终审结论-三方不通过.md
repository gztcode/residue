## 5. 诊断：缺的是「量的定义层」，不是四个维度的细节

13 条根因里，**9 条（R1 R2 R3 R4 R6 R7 R13 + R8 的计量部分）指向同一件事**：

> 四个维度共用到五个量——`T`、`K`、`J`、`a`、`b`，外加一个「已观察天数」。它们当中**没有一个被定义成「可观测事件」**：
> - **判据**：什么情况下这个量 +1 / −1（`a` 完全没有）
> - **算法唯一**：`J` 有三套式子
> - **读数源**：`a`、`b` 没有独立读数源；轮次、历史窗口没有视图
> - **写入时刻**：`b` 无写入时点；留存的「14 日内」只对执行记录有时刻
> - **计数对象**：`b` 数的是什么（候选？次扫描？）

散文 AC 的形态是「Given / When / Then + 判定」，它天然能写清**动作与可见结果**，但写不清**测量**。九个维度耦合时我以为是维度太多；现在只剩四个维度、每个维度都要靠测量来判，缺的那一层就全部暴露了。

**这不是再改一遍文字能解决的**：R1（三套式子取一，选哪个都要重定义另外两处）、R2（`a` 恒真，需要一个影子期内可执行的复检判据，属机制增补而非措辞修订）——这两条各自都需要**先定一个量的定义，再改条文**。
